A hit never prints the matched text; a hit in a file's own name is placed by the file's position in the commit's list (`line #<n>:<line>`), never by its path; a printed path is escaped.

One runner `git(...)` for every call: `--no-replace-objects`, and `-c` pairs `color.ui=never`, `log.showSignature=false`, `log.showRoot=true`, `diff.suppressBlankEmpty=false`, `core.quotePath=true`, `core.attributesFile=`; `git show` with `--attr-source=<the empty tree>`, `--no-ext-diff`, `--no-textconv`, `--no-color`, `--no-relative`, `-M`, `--ignore-submodules=none`, `--submodule=short`, `--end-of-options`; the patch also `--src-prefix=a/ --dst-prefix=b/`; the patch `--cc --full-index` (no `--text`), the file list `-z --raw --no-abbrev -M`. 4. The file list is parsed strictly (`parse_raw_records`: colons equal the parent count, modes, full-length ids, allowed statuses, paths lossless by surrogateescape, no duplicates); every patch section is matched to its record (`diff --git` path, index line ids); a disagreement is CANNOT SCAN.

A binary result is counted in one note line after the hits (`push-scan: note - <n> binary file(s) not read`) and never read. A text file git shows with hunks is read by its hunks; a text file git shows as binary, and every marked file, is read by the line diff: the result's lines added against every preimage (the intersection, position by position).

The second resolution (round 6): (L1) a marked blob is read in two views, its bytes with every NUL removed (UTF-8, replacement) and its UTF-16 decoding in the mark's byte order (replacement); an unmarked text preimage stands for both views, a binary, absent or gitlink preimage contributes nothing; the intersection is taken per view, the views united, one entry per line number, differing texts joined by a newline. (L2) A merge record with no patch section reads nothing; a single-parent record with no section is CANNOT SCAN (`the patch and the file list disagree`). (L3) A result of mode 160000 is taken first, for every status (`_gitlink_lines`); a type change keeps its two-section check. (L4) The line diff trims common ends; a pair whose middle product exceeds 1,000,000, or whose product would take the run's total past 10,000,000, is over-read (its whole middle counted as added, adding nothing to the total). ## The threat model

The scan is the pre-push guard against a commit that carries a path of this computer or the owner's name to a public remote. Untrusted inputs: every commit's content (its files, its `.gitattributes`, `.gitmodules`, names, messages and their encoding headers), the repository's and the user's git configuration, and git's own output shaped by them. A pass where a path or name stood in what the push sends is a defeated safety mechanism; a refusal or a false hit is not. Outside the model: git's own correctness for well-formed objects; a path compiled into a binary; a commit made after the scan; the scan's own code being replaced.
