## Where the increment ends

R-087's row in docs/REQUIREMENTS.md (line 113) and DESIGN C2 are the rule; the ruled behaviour, cumulative over the six briefs (handoff/TASK-067.md, round 1; handoff/TASK-067-r2.md to handoff/TASK-067-r6.md), as it now stands:

1. `push-scan.py [<base>]` (default `origin/<the default branch>`) reads every commit of `<base>..HEAD`: its message, author and committer lines, added lines and added file names, for a path of this computer (a drive-letter path, `/Users/`, `/home/`, `AppData`; a placeholder segment in angle brackets passes) and for the owner's account names (the profile folder's name, `USERNAME`/`USER`, `~/.cursor-bridge/names.txt`), never on the command line. A name equal to the remote's owner segment or to a name of the configured identity is dropped as public (the owner's decision of 2026-11-18); a name shorter than four characters is skipped with a note that does not name it.
2. Exits: 0 clean (`push-scan: OK - <n> commit(s)`), 1 on a hit (`push-scan: HIT <commit> <place> <kind>` lines, then `FOUND`), 2 where git or the base cannot be read or the patch cannot be read (`CANNOT SCAN - <reason>`). A hit never prints the matched text; a hit in a file's own name is placed by the file's position in the commit's list (`line #<n>:<line>`), never by its path; a printed path is escaped.
3. One runner `git(...)` for every call: `--no-replace-objects`, and `-c` pairs `color.ui=never`, `log.showSignature=false`, `log.showRoot=true`, `diff.suppressBlankEmpty=false`, `core.quotePath=true`, `core.attributesFile=`; `git show` with `--attr-source=<the empty tree>`, `--no-ext-diff`, `--no-textconv`, `--no-color`, `--no-relative`, `-M`, `--ignore-submodules=none`, `--submodule=short`, `--end-of-options`; the patch also `--src-prefix=a/ --dst-prefix=b/`; the patch `--cc --full-index` (no `--text`), the file list `-z --raw --no-abbrev -M`.
4. The file list is parsed strictly (`parse_raw_records`: colons equal the parent count, modes, full-length ids, allowed statuses, paths lossless by surrogateescape, no duplicates); every patch section is matched to its record (`diff --git` path, index line ids); a disagreement is CANNOT SCAN.
5. How a file is read rests on its content, never on an attribute (the first resolution): `classify_blob` is `marked` where the blob begins FF FE or FE FF, else `binary` where a NUL stands in its first 8000 bytes, else `text`. A binary result is counted in one note line after the hits (`push-scan: note - <n> binary file(s) not read`) and never read. A text file git shows with hunks is read by its hunks; a text file git shows as binary, and every marked file, is read by the line diff: the result's lines added against every preimage (the intersection, position by position).
6. The second resolution (round 6): (L1) a marked blob is read in two views, its bytes with every NUL removed (UTF-8, replacement) and its UTF-16 decoding in the mark's byte order (replacement); an unmarked text preimage stands for both views, a binary, absent or gitlink preimage contributes nothing; the intersection is taken per view, the views united, one entry per line number, differing texts joined by a newline. (L2) A merge record with no patch section reads nothing; a single-parent record with no section is CANNOT SCAN (`the patch and the file list disagree`). (L3) A result of mode 160000 is taken first, for every status (`_gitlink_lines`); a type change keeps its two-section check. (L4) The line diff trims common ends; a pair whose middle product exceeds 1,000,000, or whose product would take the run's total past 10,000,000, is over-read (its whole middle counted as added, adding nothing to the total). The 1 MiB bound and its reason are withdrawn.

Out of scope (all six briefs): `bridge_env.py` and every other program; `bridge/agents/secret-sentinel.md`, `bridge/commands/supervisor.md` and the loop's text (TASK-082, the next increment, which wires the program into the pre-push step); CI configuration.

Accepted limits, decided (grade a finding inside one as a lead, never a block): a path compiled into a binary; an unmarked text file with a NUL in its first 8000 bytes (counted as binary); UTF-16 without a byte-order mark (read as its bytes, so a path in it is not matched, whether counted or not: round 6's audit showed an unmarked ASCII file over 8000 bytes with a BOM-less UTF-16 path appended passes; HARDENING, TASK-067, ruling 1); UTF-32, and UTF-16 of the other byte order, inside a marked file; a non-ASCII name in UTF-16 of the other byte order at an odd offset; a marked binary read as text; an over-read middle may report a line its parent held (a hold, never a pass); U+010A and like code units in UTF-16 can print one hit at two line numbers.

## The threat model

The scan is the pre-push guard against a commit that carries a path of this computer or the owner's name to a public remote. Untrusted inputs: every commit's content (its files, its `.gitattributes`, `.gitmodules`, names and messages), the repository's and the user's git configuration, and git's own output shaped by them. A pass where a path or name stood in what the push sends is a defeated safety mechanism; a refusal or a false hit is not. Outside the model: git's own correctness for well-formed objects; a path compiled into a binary; a commit made after the scan; the scan's own code being replaced.
