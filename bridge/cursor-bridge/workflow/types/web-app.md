## Add at project-end.delivery for web-deployment

- **Deploy the release** (a hosted web application): the owner says yes first, since a deployment acts outside the repository and a revert does not undo it; the yes covers the deployment and the way back below, except a restore that would discard users' writes, which is asked of its own. The release's commit on `main` is deployed to the server the owner operates by the deployment procedure, recorded in `docs/INVENTORY.md` (Resources: the host, its platform and account, the command that deploys) before the first deployment; the supervisor runs it, or the owner through a run sheet where it needs a key the session does not hold. Where the release changes how stored data is kept, its migration is first rehearsed on a copy restored from a backup of the live data, kept away from the repository and the Workspace as the backup below is, which also proves the backup restores, and its result is checked there. Immediately before the deployment the owner's live data is backed up, to storage on the platform or of the owner's that Resources records with its platform and account, never into the repository or the Workspace, since it holds the users' data; from that backup until the check below passes, the product takes no writes where it can hold them (a maintenance or read-only mode), so that going back loses nothing, and the migration runs on the live data only as part of the deployment, never apart from a release (the design's migration policy, and founding rule N1's principle). The deployed product is then checked at its address with requests that change no user's data: it answers, and it reports the release's version where the design gives the version a place, the deployed commit read from the platform otherwise. A check that fails is a defect like any other, and the way back runs: where a migration ran, the backup is restored first, since the previous release may not run on migrated data, then the previous release is deployed by the same procedure; a restore that would discard writes made since the backup (the product could not hold them) waits for the owner's yes, given with what it discards stated. The report and the User Manual name the address and the version deployed.
