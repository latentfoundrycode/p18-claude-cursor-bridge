**The failure.** The failing test runs `conformance-check.py` through a symbolic link that sits in a folder holding no `bridge_env.py`. The CI output says:
- `MISSING Workflows line - not checked: .../bin/workflow-check.py: AttributeError`
- `MISSING Calibrated to the installed bridge - not checked: .../elsewhere/bridge_env.py: cannot be used (ImportError)`

**Root cause.** `_load_bridge_env` in `bridge/cursor-bridge/conformance-check.py` (lines 97-122) builds its path from `HERE = os.path.dirname(os.path.abspath(__file__))` (line 93), which is the link's folder, so through a link it finds no `bridge_env.py` and returns its stand-in module, which lacks `status_workflow_line` and `status_values`.

**Evidence.**
- `calibration_workflows_grades` (lines 755-790) has called `bridge_env.status_workflow_line` (line 787) since round 1 of this increment. Through a link that attribute is missing, hence the `AttributeError`.
- Before this increment, conformance-check took the grammar from workflow-check, which it loads by `os.path.realpath(__file__)` (lines 399, 670 and 744), so the link case worked. This is a regression of this increment.
- R-015's rule R2-2 (the docstring of the failing test) says a program run through a link loads the `workflow-check.py` beside its real file, never one beside the link. The same holds for `bridge_env.py`: loading it from the link's folder would run a file planted there.
- The supervisor confirmed the cause in a scratch copy: with `_load_bridge_env` reading `os.path.join(os.path.dirname(os.path.realpath(__file__)), "bridge_env.py")`, the linked load finds the real module.

**The reproduction test.** Windows on your host cannot create symbolic links, so the CI test above is skipped locally. The local reproduction is the supervisor's new test `tests/test_header_status.py::test_r058_r4_conformance_check_loads_bridge_env_beside_its_real_file`, in the `# --- round 4` block just above the builder's marker line, committed by the supervisor before this brief. Because it emulates the link through `os.path.realpath`, the fix must locate `bridge_env.py` through `os.path.realpath(__file__)`, as the module already does for `workflow-check.py`. Not `pathlib`'s `resolve`; not a change to the other uses of `HERE`.
