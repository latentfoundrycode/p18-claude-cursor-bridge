## Mutants file format (for TASK-030)

JSON object under `run/supervisor/<id>-mutants.json` where `<id>` matches `[A-Za-z0-9][A-Za-z0-9._-]*`:

```json
{
  "mutants": [
    {
      "id": "m1",
      "file": "demo/calc.py",
      "pairs": [{"old": "return a + b", "new": "return a + b + 1"}],
      "tests": ["tests/test_calc.py"],
      "expect_fail": ["tests/test_calc.py::test_add"],
      "expect": "survive optional reason"
    }
  ],
  "new_tests": ["tests/test_new.py::test_new"],
  "untracked": ["fixtures/data.txt"]
}
```

Summary stdout lines look like `m1: killed (ran)` or `m1: killed (cached 2026-10-26T14:00:00Z) (cached)`, then `counts: run=… cached=… killed=… survived=… not applied=… error=… expected survive=…`.

## Pytest node ids and missing tracked files

In a copy with no `pytest.ini`, pytest 9.1.1 names nodes with forward slashes relative to the copy root, e.g. `tests/test_calc.py::test_add` (verified in a minimal temp tree with `PYTHONPATH` set to the copy root).

Tracked paths absent from the working tree are skipped when building the scratch copy (not copied into the tree); they are not part of cache keys because key material uses on-disk bytes only.
