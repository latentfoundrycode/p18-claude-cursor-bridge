# BUG-045: a -h or --help word anywhere among git's words exempts every git refusal of the permission guard (R-082)

## Objective
Fix the following confirmed defect — repair the named cause, nothing else.

**Root cause, in one sentence:** `bridge/cursor-bridge/permission-guard.py:2316` sets `helpful = "--help" in w[1:] or "-h" in w[1:]`, a membership test over every word after `git`, and `not helpful` gates the refusals at 2323 (`-c core.hooksPath=...`), 2325 (`git config core.hooksPath`), 2330 (the hook skippers), 2338 (force push) and 2344 (`git worktree remove`); but git reads a help word as its help option only where it stands as an option of its own, and as an option's value (`-m -h`, `-o -h`) or after `--` it is an argument, so git does what the rest of the command says while the guard lets it through.

**Evidence** (docs/debug/BUG-045.md, found 2026-11-16 by Review A of TASK-063's records pull request, after TASK-063 merged as b05fbc8):
1. On main at b05fbc8, from a folder that is no bridge Workspace, `check(command, cwd, "Bash")` returns None (passes) for each of: `git commit --no-verify -a -m -h`, `git commit --no-verify -a -m --help`, `git commit -n -a -m -h`, `git commit --no-verify -m x -- -h`, `git -c core.hooksPath=/dev/null commit -m -h`, `git push --force -o -h origin main`, `git push --force -- --help`, `git worktree remove -- --help`, `git worktree remove -- -h`; and it refuses the same commands without the help word.

def git_subcommand(w):
    """The git subcommand and its arguments, skipping global options such as -C <dir>."""
    i = 1
    while i < len(w):
        tok = w[i]
        if tok in ("-C", "-c", "--git-dir", "--work-tree", "--namespace", "--exec-path"):
            i += 2
            continue
        if tok.startswith("-"):
            i += 1
            continue
        return tok, w[i + 1:]
    return None, []
