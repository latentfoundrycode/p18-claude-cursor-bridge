## Requirements

### Blocking (both reviews)
1. **References stay inside `bridge/` (security, blocking).** After the reference is cut and stripped as Requirement 7 of round 1 says, split the rest at `/`. One trailing `/` is allowed (a folder) and is removed before the split. Then, before any file-system call:
   - if any segment is empty, `.` or `..`, or contains `\` or `:`, the reference is a **ref** finding, with no file-system lookup at all;
   - otherwise apply round 1's placeholder rule, build the path under `<root>/bridge/`, and require that `os.path.realpath` of it lies inside `os.path.realpath(<root>/bridge)` (`os.path.commonpath` of the two equals the latter); a path outside is a **ref** finding without `exists`; only then call `os.path.exists`.
   An empty rest still means `bridge/` itself. Escape the `.` of `.claude` in `REF_RE`, so that `~/xclaude/` is not a reference.
2. **Every citation of an arrow chain is checked.** After `see "X"` (or `per`, `under`), each directly following ` → "Y"` (space, U+2192, space, a double-quoted string) is a citation too, however many there are. A citation X that does not resolve does not stop the check of the Ys after it: each is checked and reported on its own.
3. **No traceback, anywhere.** A `git_run` that returns no process (git cannot start, or the timeout ran out) at any call, the ls-tree call included, ends in exit 2 with `ERROR: git <sub-command>: <reason>` and `RESULT: not checked`. The reason says what happened: a timeout reads `timed out after <n> s`, a failure to start reads `cannot be started (<error>)`. Report the reason `git_run` gives as it is.
4. **The output order of Requirement 8.** All dropped findings first (baseline order), then all copy findings (baseline order), then new, then ref, then cite. Cite findings are in sorted path order and, within a file, in file order (the order the units stand in), never sorted by their text.
5. **The line number of a malformed entry.** The error names the line's number in the file, counted from 1: `ERROR: bridge/cursor-bridge/workflow/trace-exceptions.md: line <n>: <reason>`.
