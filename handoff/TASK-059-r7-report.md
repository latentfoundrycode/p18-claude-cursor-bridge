## Summary

Round 7 corrects Requirement 19 after round 6's regression R1: `_package_folder_rewrite` now hands each accepted folder option the rule-checked path as a word relative to the launch folder (`os.path.relpath` then `os.path.join(".", …)` except the launch folder alone as `.`), and `main` refuses with `KNOWN_RUNNER_REFUSE` when `relpath` raises, so launch-folder spaces and cmd.exe metacharacters never appear on the rewritten command line while runners still resolve the same checked folder from their working directory.

## Requirement 19 (amended)

- (a) `_package_folder_rewrite` still computes the same `abs_path` as the scan's `run_dir` and, at lines 374–378, replaces the option value with `os.path.relpath(abs_path, base)` so only a path under the launch folder is handed and no segment of the launch folder's own path is copied onto the command line.
- (b) At lines 379–384 the handed word is `"."` when `rel == "."` and otherwise `os.path.join(".", rel)`, giving `.\frontend` or `./frontend` and never a value starting with `-` alone.
- (c) The `ValueError` branch at lines 376–378 returns `(None, label)` with the same option label as the scan; `main` at lines 2159–2162 writes `KNOWN_RUNNER_REFUSE` with that label and returns 125 before `_cmd_exe_refuse_word` and before anything starts, with no absolute fallback.
- R1 is removed because the cmd.exe line and check see only dot-relative folder words (not the absolute launch or npm install paths), while `os.path.abspath` normalization of `frontend/..` to the launch folder and the `.`-prefixed relative word still match the path `_package_folder_ok` and `_link_walk_ok` already checked.
