### What is compared
3. **Homes.** The *current homes* are:
   - `bridge/commands/supervisor.md` in the working tree;
   - every `*.md` file under `bridge/cursor-bridge/workflow/`, recursively, except `bridge/cursor-bridge/workflow/trace-exceptions.md`.

   The *baseline homes* are the same paths at the baseline commit: `bridge/commands/supervisor.md` and every `*.md` path that `git ls-tree` lists under `bridge/cursor-bridge/workflow/` there, except `trace-exceptions.md`.

   The *traced passages* are the units (Requirement 4) of the baseline `bridge/commands/supervisor.md`, every one of them. The *baseline unit set* is the units of all baseline homes.

   The *module files*, the only files checked for new text, are the current `*.md` files under `bridge/cursor-bridge/workflow/phases/`, `workflow/types/` and `workflow/traits/`, recursively.
4. **Units.** A file is read as UTF-8 with universal newlines, with any byte-order mark dropped. It is cut into units line by line, in this order of tests:
   - **Fenced block.** A line whose content after stripping leading spaces starts with three or more backticks or three or more tildes opens a fenced block. The block closes at the next line whose stripped content starts with at least as many of the same character. An unclosed block runs to the end of the file. The whole block, opening and closing lines included, is one unit. Nothing inside it is a heading.
   - **Heading.** Outside a fenced block, a line matching `^ {0,3}#{1,6} ` is a heading. It is never a unit. It ends the current unit and sets the section (below). Its *text* is the part after the `#` run and the space, stripped.
   - **Not a unit.** A blank line ends the current unit. So does a line that, stripped, is three or more of only `-`, only `*` or only `_` (a thematic break, including front-matter fences). Neither is a unit.
   - **Table.** A run of consecutive lines whose stripped content starts with `|` is one unit.
   - **List item.** A line whose stripped content matches `^([-*+]|[0-9]+[.)])\s` starts a new unit.
   - **Paragraph.** Any other line continues the current paragraph or list-item unit, or starts a new paragraph unit.

   A unit's **normal form** for comparison:
   - for a fenced block, each line with trailing whitespace removed, joined with `\n`;
   - for every other unit, each line stripped, joined with one space, and every run of whitespace collapsed to one space.

   So a hard-wrapped paragraph and the same paragraph written on one line are equal. That matters because rule 30 forbids hard wraps in new Markdown.

   Each unit has a **heading chain**: the texts of the headings above it that are still open, from level 1 down. A heading closes every open heading of its level or deeper. A unit is *in section H* of its file when H is one of the texts in its chain.
5. **The findings.** Counts compare normal forms exactly. For a traced passage `t`:
   - `b` is the number of units equal to `t` in the baseline homes;
   - `c_all` is the number of equal units in the current homes;
   - `c` is the same count leaving out units that stand in an excused section (Requirement 6).

   Each traced passage `t` with distinct normal form gets exactly one finding at most:
   - **dropped**: `c_all == 0`, unless a `reword` entry excuses it (Requirement 6). A dropped passage that an entry excuses prints a NOTE line, not a FAIL.
   - **copy**: `c > b`. The passage stands in more places than at the baseline, whether in one file or several.

   Then, for each unit of a module file whose normal form is not in the baseline unit set and which does not stand in an excused section:
   - **new**: the unit is new text in a module.

   Text that is new in `bridge/commands/supervisor.md`, or in `.md` files directly under `workflow/`, is not flagged: R-029 asks for new text "to the modules".

   The comparison is **incremental** in this sense: it always compares the fixed baseline with the tree as it stands, so it is valid at every intermediate state of the split. A passage not yet moved is found in the core, its home. A passage moved once is found in its module. A passage moved twice, with its earlier home emptied, is found once under `workflow/`. Each increment from TASK-010 on runs the check and must leave it green. It never compares with the previous increment or with any commit but the baseline.
6. **The exceptions file.** Everything up to the first line that is exactly `## Entries` is prose and is not read. Every non-blank line after it must be an entry of exactly this form:

   `- <kind> <id> <file> <heading>`

   - `<kind>` is `reword` or `new`.
   - `<id>` is the increment's id, matching `[A-Z][A-Z0-9]*-[0-9]+` (e.g. `TASK-010`).
   - `<file>` is a repository-relative path with `/` separators and no spaces. It is either `bridge/commands/supervisor.md` or a path ending `.md` under `bridge/cursor-bridge/workflow/`.
   - `<heading>` is the rest of the line, stripped and non-empty: a heading's text as Requirement 4 defines it, e.g. `- reword TASK-010 bridge/commands/supervisor.md Main and conditional workflows`.
   - Single spaces separate the first four fields.

   Any other line after `## Entries` is an input error (Requirement 9) naming the line number. So is a file with no `## Entries` line.

   What an entry excuses:
   - **Both kinds.** Every unit of the *current* `<file>` that is in section `<heading>` stands in an *excused section*. It is never reported **new**, and it is not counted in `c`. That is how an entry explains a copy.
   - **`reword` only.** Every traced passage that is in section `<heading>` of the *baseline* `<file>`, and is found nowhere now (`c_all == 0`), is excused from **dropped**. A `new` entry never excuses a dropped passage.

   An entry whose file or heading exists in neither the current nor the baseline tree excuses nothing and is not itself a finding. A passage reworded while it moves needs two `reword` entries:
   - one naming its baseline place (`bridge/commands/supervisor.md` and its baseline heading), for the vanished text;
   - one naming its new place, for the new text.

   The dropped and new findings print exactly those file and heading pairs (Requirement 8).
7. **References and citations**, in every current home file:
   - **`~/.claude/` references.** A reference is `~/.claude/` followed by the longest run of characters that are none of: whitespace, `` ` ``, `'`, `"`, `(`, `)`, `[`, `]`, `,`, `;`. Then strip any trailing `.` and `:`. Map it to `bridge/<rest>` under the repository root.
     - If a `/`-separated segment contains `<`, `>`, `*` or U+2026, or is `...`, it is a placeholder. The reference then resolves when the folder made of the segments before the first placeholder exists.
     - Otherwise it resolves when `bridge/<rest>` exists as a file or a folder. An empty rest means `bridge/` itself.

     Search the file's raw lines, fenced blocks included. A reference that does not resolve is **ref**. Both of today's placeholder forms resolve.
   - **Citations.** In each unit's normal form, a citation is the word `see`, `per` or `under` (any case, as a whole word), one space, then a double-quoted string `"X"`. Each further ` → "Y"` that follows directly is also a citation.
     - A citation resolves when some heading (outside fenced blocks) in any current home has text equal to X, or beginning with X followed by ` — ` (space, U+2014, space).
     - One that does not resolve is **cite**.

   Write the non-ASCII characters as escapes in the source (`"…"`, `"—"`, `"→"`). The program text stays ASCII.

### Output and exit codes
8. Output, in this order:
   - With `--map`, one line per traced passage in baseline order: `MAP <home>[, <home>...]: <baseline heading> - <excerpt>`. `<home>` is each current path where it stands; for a dropped passage it reads `-`.
   - The findings, in this order: dropped (baseline order), copy (baseline order), new (module files in sorted path order, then file order), ref, cite (both in sorted path order, then file order). Each finding has one of these forms:
     - `FAIL (dropped) bridge/commands/supervisor.md: <baseline heading> - <excerpt>`
     - `FAIL (copy) <path>, <path>[, ...]: <baseline heading> - <excerpt>` (every current path where it is counted)
     - `FAIL (new) <path>: <heading> - <excerpt>`
     - `FAIL (ref) <path>:<line>: <reference>`
     - `FAIL (cite) <path>: <heading> - "<X>"`
   - For each excused dropped passage: `NOTE (reword <id>) bridge/commands/supervisor.md: <baseline heading> - <excerpt>`.
   - A summary line: `TRACED: <n> passages of baseline <first 7 characters of the commit>; <k> in supervisor.md, <m> under workflow/, <d> dropped, <e> excused`.
   - The final line: `RESULT: OK` when no FAIL line was printed, else `RESULT: <n> problem(s)`.

   The `<baseline heading>` and `<heading>` fields:
   - `<baseline heading>` is the deepest heading text of the passage's baseline chain;
   - `<heading>` is the deepest of the unit's current chain;
   - either reads `-` when the chain is empty.

   `<excerpt>` is the first 60 characters of the normal form. Every printed field is ASCII: a non-ASCII character is written as its backslash escape (`—`), as Python's `backslashreplace` writes it. Output order is deterministic.
9. Exit codes:
   - `0` when no FAIL line is printed; NOTE lines may be.
   - `1` when there is at least one FAIL line.
   - `2` when the check cannot run. Then print `ERROR: <what>: <reason>` lines and `RESULT: not checked`, and never a traceback. The causes:
     - the root is not a git work tree;
     - `git` cannot be started;
     - `trace-baseline.txt` is missing or not in the form of Requirement 2;
     - the baseline commit is absent from the repository. Say so, naming a shallow clone as the likely cause;
     - `bridge/commands/supervisor.md` is missing at the baseline or now;
     - the exceptions file is missing or breaks Requirement 6;
     - a home cannot be read as UTF-8 (now or at the baseline);
     - a usage error.
10. **Git.** The program may run exactly these, each as `["git", "-C", <root>, ...]`, with `capture_output`, `stdin=subprocess.DEVNULL`, a timeout, and `creationflags=getattr(subprocess, "CREATE_NO_WINDOW", 0)`:
    - `rev-parse --is-inside-work-tree`
    - `cat-file -e <sha>^{commit}`
    - `ls-tree -r -z --name-only <sha> -- bridge/cursor-bridge/workflow/`
    - `show <sha>:<path>` for a path `ls-tree` listed or `bridge/commands/supervisor.md`

    Baseline file bytes are decoded as UTF-8 (BOM dropped, `\r\n` read as `\n`). Nothing else is launched.
