# TASK-059: The launcher's command forms: the interpreter's flags and a suite in a subfolder (R-078)

## Objective
`bridge/cursor-bridge/bridge-run.py` (the launcher) runs a test suite only when it knows the suite by name, and holds every test run to its target rule: a run reads the project's own tests, never a folder outside the launch roots. Two forms a project's suites need are not served today. First, the interpreter's own leading flags: `python -B -X utf8 -m pytest -q` is refused (the launcher reads `argv[1:3]` and sees `-B`), and for the driver kind `python -B run/supervisor/x.py` is refused (`resolve_driver_program` refuses `argv[1]` that starts with `-`). Second, a suite in a subfolder: `npm --prefix frontend test` is refused (the leading form is no named suite), while the trailing form `npm test --prefix <any folder>` is accepted for any folder, outside the Workspace included, which breaks the target rule. This increment makes the launcher accept exactly the two interpreter flags `-B` and `-X utf8`, with every reading of the command starting after them; reads npm's, pnpm's and yarn's folder options wherever they stand and holds the folder to the target rule; holds the environment names that move such a runner's folder to the same rule; gives a refused option of a runner the launcher knows its own exit-125 message (a defect to report) apart from the unknown runner's (run it directly, `# wake`); writes `merge_ids` sorted; and escapes the root of both plan globs. The supervisor's acceptance tests are written and committed; your work is to make them pass without breaking the existing ones.

Satisfies: R-078 - The launcher accepts the forms a project's suites need and holds each to the target rule (C6, F5, J4, J9, J12): the test and the driver kind accept the interpreter's own leading flags, exactly `-B` and the two words `-X utf8`, every reading of the command starting after them, and no other interpreter option; npm's `--prefix`, pnpm's `--dir` and `-C` and yarn's `--cwd` are read wherever they stand before a bare `--` and refused (exit 125) unless the folder lies under the launch roots by its resolved path, through no link, given once, the `=` form alike, and an environment name that moves the folder one of the three runners executes in, each found by the increment's reality check from the tool's documentation and a probe and listed in the inventory's row for the target rule, is held to the same rule in the run's environment, a value that does not resolve refused, the variable named and its value never printed, a configuration file a runner finds staying outside the rule as that row says; the exit-125 message tells a refused option of a known runner (a defect to report, never a run to start by hand) from an unknown runner; `merge_ids` is written sorted; the plan glob escapes its root; `reflection.md`'s demonstration sentence names the `-B` form. ## Requirements
1. **One helper for the interpreter's flags (C6).** One helper in `bridge-run.py` reads, for a command whose head is `python`, `python3`, `py` or the project's own `.venv` python, the leading words `-B` and the two words `-X utf8`, in any order, each at most once, and returns where the command proper begins (and, where a word stops it, that word). Accepted leads are exactly: none, `-B`, `-X utf8`, `-B -X utf8`, `-X utf8 -B`.
2. **Every reading starts from that place.** `named_suite`, `test_suite` (with its `-p no:` exception), `runner_word`, `outside_target`, `outside_by_environment` (through `runner_word`), `head_text`, and the driver kind's `resolve_driver_program`, `main`'s substitution of the program's absolute path (today `cmd[1] = driver_prog`) and `verify_driver_program_abs`'s reads in `main` (today of `cmd[1]`) all read the command from the place the helper returns, so the program the driver kind checks and starts is the word after the flags, and release S's target and environment rules see the runner behind the flags. The logged head is the head the command has without the flags: `python -B -X utf8 -m pytest -q` logs `python -m pytest`.
3. **Every other interpreter option is refused** (exit 125) before the module or the program: `-B` twice, `-X utf8` twice, `-Xutf8`, `-X dev`, `-X utf8=1`, a bare `-X`, `-E`, `-I`, `-O`, `-u`, `-S`, and any other. The launcher sets no `PYTHONUTF8` and never adds a flag itself; the flags given reach the child interpreter as given (a suite launched with both runs with `sys.flags.dont_write_bytecode == 1` and `sys.flags.utf8_mode == 1`).
4. **The folder options (F5).** For npm: `--prefix` and `-C`. For pnpm: `--dir` and `-C`. For yarn: `--cwd`. Each is read wherever it stands before a bare `--` (after a bare `--` it is the script's own argument and is not read), before or after the subcommand, in the two-word form and the `=` form (`-C=<folder>` included). A long option word whose name (the part before any `=`) is a leading part of the folder option's long name and is at least three characters long with its dashes is read as that option: `--p`, `--pr`, `--pre`, `--pref`, `--prefi` for npm's `--prefix`; `--d`, `--di` for pnpm's `--dir`; `--c`, `--cw` for yarn's `--cwd`. The attached form `-C<folder>` is refused, unread.
5. **The leading form is a named suite.** `named_suite` recognises the folder options before the subcommand: `npm --prefix frontend test`, `npm -C frontend run test:unit`, `pnpm --dir x test`, `yarn --cwd x test` are named suites, the folder options (and only they) skipped before the subcommand. Any other word before the subcommand leaves the command unnamed, as today.
6. **The folder rule.** The folder is accepted only where it exists as a folder, lies under the launch roots (`launch_roots`) by its resolved path, and every component from the launch folder to it is reached through no link (a symbolic link or a junction, `bridge_env.is_link`), a link that leads back inside included. A relative value is read against the launch folder. Each of these is refused with exit 125 before anything starts: a folder outside the roots; a link on the way; a folder that does not exist; the option given twice (an option and its other name count as one option, so `-C x --prefix x` is twice); a missing value (the option as the last word, or `--prefix=` with nothing after it); the attached `-C<folder>`.
7. **A suite so launched** is stripped, logged and limited as any named suite: its run log row has kind `test`, the limit given, and `head_text` logs `npm test` (or `npm run test:unit`, `pnpm test`, `yarn test`), never the folder option or its value.
8. **The environment names (F5, the reality check).** For an npm run: `npm_config_workspace` and `npm_config_workspaces`. For a pnpm run: `npm_config_workspace_dir`. For a yarn run: none. Names are compared without regard to letter case, the later of two spellings read, as `outside_by_environment` reads today. The rule reads the run's environment as `main` already builds it for that function (the launcher's own environment with a key file's lines added). A name with a value is refused where the value resolves outside the launch roots, resolves inside through a link, or does not resolve to an existing folder (a package name, `true`). A relative value is read against the folder the runner runs in: the folder option's folder where one is given, else the launch folder. An empty value is no value, as today. The refusal names the variable as `outside_by_environment` returns it today (upper case) and never prints the value. `npm_config_prefix`, `NPM_CONFIG_PREFIX`, `npm_config_local_prefix` and `INIT_CWD` are not refused. Configuration files stay outside the rule: read none.
9. **The two exit-125 messages (J4).** A refused option of a runner the launcher knows gets a message whose first words are exactly `bridge-run: refused - the launcher knows this runner and refuses ` followed by the refused word as given (for example `-p`, `-X`, `--prefix`, `--pre`; for a refused `=` form or attached form, the word as typed holds the option's name), and that says it is a defect to report, never a run to start by hand (the word `defect` stands in it), with no `# wake` anywhere on stderr. The cases: an escape option of a named suite that `test_suite` refuses (`pytest -p evil`, `python -m pytest -c x.ini`); an interpreter option other than the two before `-m pytest` or `-m unittest` (a python head whose words, read past its options, reach `-m pytest` or `-m unittest`), the refused word named (`python -X dev -m pytest` names `-X`, `python -E -m pytest tests` names `-E`, `python -B -B -m unittest` names `-B`); every refusal of the folder rule (Requirement 6). Every other refusal of an unaccepted command keeps today's message unchanged, beginning `bridge-run: refused - the launcher runs only cursor-agent`, with its advice to run directly in the background marked `# wake` (`make test`, `python -c print(1)`, `npm run dev`, `bash -c true` all keep it). The driver kind keeps its own refusal (`DRIVER_REFUSE`). The environment rule's refusal (Requirement 8) may keep its present message or say more; it names the variable and never the value.
10. **No value printed.** No refusal of the environment rule prints a variable's value, on stderr or stdout.
11. **`merge_ids` sorted (J9).** The builder row's `merge_ids` is written as a sorted list, whatever order the brief's `Merge unit:` line gives and whatever the hash seed (today `"merge_ids": tuple(declared)` from a frozenset).
12. **The launcher's plan glob escapes its root (J12).** `builder_review_refusal`'s header check escapes the folder part of its pattern (`glob.escape`), so a Workspace whose path holds `[` reads its plan.
13. **`bridge_env.plan_increment_ids` escapes its root (J12)** the same way. In `bridge_env.py` nothing else changes.
14. **The manifest** is regenerated with `python tools/make-manifest.py`; `VERSION` is unchanged.
