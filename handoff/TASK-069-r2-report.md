## Summary

A `PR-<n>` with no launcher row, guard round or pass line still starts at its commit for the Started column, and that commit time is no longer a known start, so the Mean days column does not take a zero from it. A name beginning `STAGE-` or `DESIGN-` is not a counted name from a brief, a guard record or a pass line, so it starts nothing and its rounds enter no cause line, while its passes still count. A stage review or a design critique is no counted name. `_review_only_name` (lines 537-539) is a name beginning `STAGE-` or `DESIGN-`. `_pace_names` leaves those names out of the counted set from briefs (lines 733-735), guard records (`_guard_name_ids`, lines 676-682) and pass lines (lines 737-739), and out of merges (lines 792-793). The over-ceiling and stage lists are unchanged.
3. The `PR-<n>` rule holds in both modes. The module docstring (lines 18-20) says a squash closing `(#<n>)` whose subject names no ID the reader finds is merged as `PR-<n>` with `handoff/` tracked or untracked. `_pace_names` already did that: with `handoff/` untracked the reader's IDs occupy the commit (lines 750-753) and a subject that names none stays in `own` (lines 754-758) and is merged (lines 800-805). No code change for this correction.
4. The in-flight log's bound is in bytes. `_read_pass_lines` (lines 602-614) reads `run/supervisor/in-flight.md` in binary, at most `_IN_FLIGHT_CAP + 1` bytes (`_IN_FLIGHT_CAP` is 8388608, line 101), then decodes with `errors="replace"`. `_PASS_RX` (lines 111-113) matches the stamp with `[0-9]`, not `\d`. The module docstring states the byte cap (lines 69-72).
5. The guard's read of the round's cause is bounded and linear. `_SCOPE_CAUSE_CAP` (line 126) is 1048576. `_round_cause` (lines 787-810) reads the first SCOPE file in binary, at most that many bytes plus one, and returns `unstated` when the file is missing, unreadable or longer. `_cause_on_first_line` (lines 765-784) takes the first line that begins `Round cause:`, strips spaces and tabs, then applies the longest cause first and the same separators, with no regular expression. The snapshot docstring states the bound (lines 37-43). A snapshot is not refused for the cause.
6. The ISS-013 case's docstring. `tests/test_pace_report.py`, `test_r044_iss013_form_merges_nothing_with_plan_check` (lines 143-146), now says the subject merges no increment and is counted as its pull request, `PR-61` (R-089). The assertion on line 156 is unchanged.
