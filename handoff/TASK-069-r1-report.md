## Assumed, not verified

- A seeded guard round is not a start, not a cause record, not a pass, and does not hold its round against a `review-b` pass line. The brief says non-seeded only for starts, and every acceptance guard record is unseeded. A seeded round with a stated cause and a `review-b` pass line of the same number would confirm it.
- Where several builder rows of one round each state a cause, the first stated cause in log order is kept, not the last row. The release S relaunch states a cause only on the later row (`unstated`, then `fix-induced`), so both readings match that case. Two stated causes on one round would confirm it.
- Where `refs/heads/main` has more than one commit closing with the same `(#<n>)`, the earliest decides the fold and the merge time. Every acceptance pull request has one such commit. An earlier commit that names a counted name and a later one that names none would confirm it.
- An ID the subject reader returns only from a trailer sorts after every counted ID that stands in the subject, and IDs with no position then sort by their text. No acceptance subject names a counted name only through a trailer. A `Merges` trailer holding the only counted name would confirm it.
- A builder row or a guard round whose name is a folded `PR-<n>` is counted under the name the pass lines fold into. The brief requires the pass lines and their causes to fold, and does not mention the pull request's own launcher row or guard record. A launcher row whose brief is `PR-<n>`, beside a squash that names an increment, would confirm it.
- A non-seeded guard entry whose `time` does not parse holds that round against a `review-b` pass line and is not itself a pass. Every acceptance guard time parses. An entry with an empty `time` and a `review-b` pass line of that round would confirm it.
- With `handoff/` untracked, an ID the subject reader returns occupies the commit for folding, so `PR-<n>` is not a second name beside the ID the old rule already merges. The acceptance projects all track `handoff/`. An untracked `handoff/`, a subject that names an ID, and a pass line `PR-<n>` for that commit would confirm it.
