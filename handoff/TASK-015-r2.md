## Requirements
R2-1. **No path twice, a module in its place.** Before any file line is printed, every module path of the phase is taken as already printed. A pointer path equal to one of the phase's own modules (`project-end.md`, `reflection.md`, the module's own name) is therefore never printed from a pointer line; each module is printed once, in table order, with its note where Requirement 2(b) gives one. The rule "a path already printed is not printed again" now covers the modules too.

R2-2. **Everything that uses the loaded checker fails open as one.** Every call into the loaded `workflow-check.py` and every read of its tables (the open list and registry reads, `load_tables`, the pointer-line reading of every module, `collect_conditional_files`) runs inside one `try ... except Exception`. On any exception there: no pointer-line file and no conditional file is printed (none found before the exception either: collect the lines first, print them only when the whole reading succeeded), and the part prints the one cannot-read line of Requirement 7, which names `~/.claude/cursor-bridge/workflow-check.py` and the exception's type name (for example `~/.claude/cursor-bridge/workflow-check.py: cannot be used (AttributeError)`); the rest of the part is printed as usual. The load failure keeps its own line as in round 1. The line contains no `lines ` and does not begin with `  - `.

R2-3. **The cannot-read line names its file in the `~` form.** The file the line names is shown as `~/.claude/cursor-bridge/...` with forward slashes, built from the hook's own knowledge of which file it was reading (the open list, the registry, `workflow-check.py`), never from an absolute path a function returned. No absolute path appears anywhere in the pointers part.

R2-4. **A link anywhere below `~/.claude/cursor-bridge/workflow/` refuses what lies behind it.**
- A conditional candidate is named only if none of these is a link (`is_link`): the `workflow/` folder, the layer folder (`types/` or `traits/`), for a sub-type the `types/<type key>/` folder, and the file itself.
- A phase module's pointer lines are read only if none of these is a link: the `workflow/` folder, the `phases/` folder, and the module file. A module reached through a link is still named; it contributes no pointer-line file. No cannot-read line is printed for it.

R2-5. **Only a well-formed key becomes a path part.** A type, sub-type or trait key taken from the open list is used in a path only if it matches `^[a-z0-9-]+$`; a candidate whose key does not is skipped, with no line printed. The open list is still read; this is not a cannot-read case.

R2-6. **The docstring is ASCII at run time.** Write the arrow in the docstring as `U+2192` (the program's string constant stays `"\u2192"`), then run `python tools/dump-cli.py`; `docs/CLI_REFERENCE.md` and `docs/cli-reference.json` then hold no arrow from this docstring.

R2-7. **Your report.** In `handoff/TASK-015-r2-report.md`, correct round 1's second assumption: a trailing `;` (`Sub-files: a.md; b.md;`) leaves the text `b.md;`, which fails the pattern, so `b.md` is ignored too; say whether you keep that reading (it follows Requirement 4's "any other path on the line is ignored") or not.
