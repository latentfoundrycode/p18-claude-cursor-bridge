# BUG-034 — the installer replaces a release of the same version without keeping the way back

## Objective
Fix the following confirmed defect — repair the named cause, nothing else. Root cause: `install()` in `bridge/cursor-bridge/bridge-install.py` (lines 599-615 at HEAD) keeps the installed release as the way back (`save_previous`, and the "changed on this computer" check before it) only under `if old_version and old_version != new_version:`, so a release folder that carries the installed release's version string but other files replaces the installed tree with no previous release kept. This was found by TASK-026's release-level review, pass 1, finding M2, and the supervisor reproduced it. Evidence: main between merges and its stamp is such a folder (its VERSION and MANIFEST.json say 2026.10.25a while 144 files differ from the installed 25a's 108); installing it prints no `previous ... kept` line, bridge-check then reports the new tree as the old version, and `--rollback` answers that there is nothing to roll back to, so the way back, a safety mechanism, is lost without a word. Reproduction: `tests/test_bug034.py::test_bug034_a_release_of_the_installed_version_with_other_files_is_refused` fails on the current code (the install runs and exits 0) and must pass; `tests/test_bug034.py::test_bug034_the_same_release_installed_again_is_still_allowed` and `tests/test_bug034.py::test_bug034_anyway_installs_it_for_the_maintainers_rehearsals` pass today and must keep passing. The supervisor wrote and committed `tests/test_bug034.py` before your run; read it whole before you start.

## Requirements
1. When the target holds an installed manifest whose version equals the release folder's (`new_version`), `install()` compares the installed manifest's file fingerprints (as `fingerprints_of(target)` reads them) with the release folder's (`fingerprints`, already read at line 582). It compares the two manifests, not the files on disk. The two are different when a file is listed in one and not the other, or when a file is listed in both with another fingerprint.
2. Equal: the install proceeds exactly as today (a repeated install, the repair the installer's other messages name).
3. Different, and `--anyway` not given: the install is refused with exit 2 before anything is changed. The refusal comes before the `bridge-install: <release> -> <target>` line, before `save_previous` and before `replace_release`; no file under the target is written, rotated or removed. The refusal is one sentence (one `print`) starting `bridge-install: `. It says that the release folder carries the version of the release installed now (naming that version) but not its files (the count of differing files and a few of their relative paths, through the existing `few()`); that a release with other files is stamped with a new version before it is installed, so that the release installed now is kept as the way back; that `nothing was changed` (this exact lowercase phrase; the reproduction test looks for it); and that `--anyway` installs regardless (the maintainer's rehearsals). ASCII only.
4. The refusal applies under `--dry-run` too: the same sentence, exit 2.
5. With `--anyway` the install proceeds exactly as today, whether the manifests are equal or not.
6. A target with no readable installed manifest (a first install) and a target of another version behave exactly as today, the S4 check, `save_previous` and their messages included.
7. The module docstring's item 1 states the new condition: a release of the installed version is installed only when its manifest lists the same files with the same fingerprints, and any other is refused before anything changes, `--anyway` excepted. Keep it ASCII and in the docstring's existing style. No other part of the docstring changes.
8. After your last edit under `bridge/`, regenerate the stamp with `python tools/make-manifest.py` and the command reference with `python tools/dump-cli.py`, as in Done.
