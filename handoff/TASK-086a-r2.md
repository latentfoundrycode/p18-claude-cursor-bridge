4. **git's answers (defect; both reviews; `test_task086a_git_answering_neither_yes_nor_no_cannot_be_read`).** Every git call has exactly the answers git defines and nothing else counts as one: `merge-base --is-ancestor` exit 0 is yes and exit 1 is no; `rev-parse --verify -q <name>` exit 0 is found and exit 1 is not found; `symbolic-ref -q HEAD` exit 0 is a branch and exit 1 is a detached head; `merge-base <a> <b>` exit 0 with a commit is the base and exit 1 is no common ancestor; `ls-tree` and `rev-parse --show-toplevel` exit 0 only. Any other exit, a timeout, or a failure to start is git not answering: the set cannot be read with the cause `git` (R4), wherever the call stands, the drop rule, the base, the report lists, the branch and the new-branch check included. The new-branch check's result is read only when it is a list: a git that does not answer there ends the resolve as R4 says, never a `TypeError`.

5. **The branch, `main` and start commits by their full names (security; security audit advisory; `test_task086a_main_and_the_branch_are_read_by_their_full_ref_names`, `test_task086a_a_start_commit_is_a_full_object_name`).**
   - The branch is read with `git symbolic-ref -q HEAD`: its output `refs/heads/<name>` gives `<name>`; exit 1 is a detached head (cause `detached`). `current_branch()` and `built_by` stay as they are (R13).
   - The base is the merge base of `refs/heads/<branch>` with `refs/remotes/origin/main` where that ref exists, or else with `refs/heads/main` where that one exists; where neither exists, or the merge base has no common ancestor, the base cannot be found (cause `main`). A tag or another ref named `main` or `origin/main` is never read.
   - A `start_commit` places a row only where it is a full object name: `re.fullmatch(r"[0-9a-fA-F]{40}|[0-9a-fA-F]{64}", value)` on a string. Anything else (shorter, longer, not hexadecimal, not a string) is a row whose start commit names no commit: never dropped, it drops nothing.

6. **The record read as bytes, a line at each line feed (security; security audit blocking 4, Review A should-fix; `test_task086a_a_hostile_record_line_makes_the_set_unknown_and_the_repair_moves_it`, `test_task086a_a_record_line_split_only_at_its_line_feed`, `test_task086a_the_unknown_cause_names_the_record_given_by_run_log`).** Read the record in binary and split it at `b"\n"` alone (never `splitlines`, which also splits at U+2028, U+0085 and others). A line that is empty or holds only whitespace is skipped. Each other line is decoded as UTF-8 strictly; a line that does not decode, that `json.loads` refuses (`ValueError`, `RecursionError`), or that is not a JSON object is a line that does not parse. 7. **The repair loses nothing and writes nothing outside the record's folder (security; security audit blocking 3 and advisory; `test_task086a_a_repair_that_fails_part_way_leaves_the_record_whole`, `test_task086a_a_repair_refuses_a_damaged_file_linked_to_another_file`).** In this order: read and sort the lines as correction 6 says (where every line parses, change nothing, print both counts, exit 0); refuse, before any write, a `runs.damaged.jsonl` that exists and is not a regular file, is a symbolic link or junction (`os.path.islink`, and `os.lstat`'s `st_reparse_tag` where present), or has more than one hard link (`st_nlink > 1`); append the moved lines, each as its original bytes followed by `b"\n"`, to `runs.damaged.jsonl` opened with the built-in `open` in `"ab"` mode, then flush and `os.fsync`; write the kept lines, each as its original bytes followed by `b"\n"`, to a temporary file made by `tempfile.mkstemp(dir=<the record's folder>, prefix=<the record's name> + ".")`, flush, `os.fsync`, close; `os.replace` it over the record; print both counts; exit 0.
