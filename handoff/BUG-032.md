Each fix is the minimum that removes its cause; nothing else changes "while you are there".

1. **A checkpoint run is refused when a copied conftest.py imports what the increment adds.** Root cause: BUG-030's `archive_checkpoint` (`bridge/cursor-bridge/mutation-run.py`) copies the working tree's conftest.py files on the way to each new test over the checkpoint's archive; `run_resolution_check` refuses any pytest exit other than 0 or 2 (`if rc not in (0, 2): raise Refuse("mutation-run: resolution check failed (pytest exit %d)" % rc)`), and `checkpoint_collect_refused` excuses only exit 2, so a copied conftest.py that cannot load on the old code refuses the whole run, where the tests it guards cannot be run against the checkpoint and are, by the checkpoint step's rule for a collection error, `not run`. Evidence: the run prints `mutation-run: resolution check failed (pytest exit 4)`; exit 4 is pytest's usage-error exit, which it gives when a conftest.py fails to import at startup ("ImportError while loading conftest"), so the copied file was read and failed to load. Reproduction: `tests/test_bug032.py::test_bug032_a_conftest_importing_what_the_increment_adds_lists_its_tests_not_run` (the working tree adds `demo/newmod.py` and a `tests/conftest.py` that imports it; the new test `tests/test_six.py` uses its fixture: exit 2 today, must list the test `not run` and not be refused).
2. **scope-check.py opens a builder window for a launch that never got the slot.** Root cause: `builder_windows` (`bridge/cursor-bridge/scope-check.py`) takes every `kind: builder` row, a `"slot": "not free"` row included (the launcher's exit-123 row of a launch that waited and gave up, which started no command), and its window runs `waited` + `seconds` + 120 seconds from its `id`; BUG-030 made `roster-check.py` `built_by` and `bridge-run.py`'s `class_used` skip such a row. Reproduction: `tests/test_bug032.py::test_bug032_a_launch_that_never_got_the_slot_opens_no_builder_window` (a started row opens one window, the precondition; a `slot: not free` row opens one today, must open none).
3. **pace-report.py reads a launch that never got the slot as a launch.** Root cause: `_lift_map` and `_start_times` (`bridge/cursor-bridge/pace-report.py`) read every row of the ID from `runs.jsonl`, a `"slot": "not free"` row included, so a refused launch's `lift` becomes its round's lift and its time the increment's start. Reproduction: `tests/test_bug032.py::test_bug032_the_pace_report_reads_a_launch_refused_the_slot_as_no_launch` (a refused row with `lift` class before a started row without: `{1: 'class'}` today, must be `{1: 'none'}`; the start must be the started row's).
4. **The branch rule refuses the refactoring pass's second candidate and its snapshot.** Root cause: `bridge_env.branch_allows_id` (`bridge/cursor-bridge/bridge_env.py`), which `bridge-run.py` and `review-guard.py` both call, allows only the IDs the branch's first brief declared (`branch_declared_ids`) until they merge; a `Merge unit:` line admits only the plan's increment IDs (bridge-run.py), and a REFAC ID is never one; the stage-close refactoring pass cuts one branch `refactor/<stage>` and delegates one `handoff/REFAC-<nnn>.md` per candidate on it (refactoring-pass.md step 4), then takes one snapshot of the whole branch named `REFAC-<stage>` (step 6), so the second REFAC brief is refused (`branch rule: REFAC-004 is not on this branch (counted: REFAC-003)`) and the guard refuses the snapshot for the same reason. Reproduction: `tests/test_bug032.py::test_bug032_a_refactoring_branch_takes_every_candidates_brief` (REFAC-004 refused today on `refactor/B5`, must run; TASK-005 there refused, and REFAC-004 after REFAC-003 on `task-003` refused, the preconditions) and `::test_bug032_the_refactoring_pass_snapshot_is_taken_on_its_branch` (a snapshot `REFAC-B5` on that branch must be taken; one of TASK-005 refused, the precondition).

Satisfies: R-040 — one heavy job at a time on the computer, through the launcher's machine-wide slot (cause 2: a launch refused the slot runs nothing); R-041 — mutation reruns run through `mutation-run.py`, the new tests run once against the checkpoint's code (cause 1); R-042 — the code gate's round ceiling held by programs, the branch rule refusing a brief or a snapshot under an ID outside the branch's set (cause 4); R-044 — the pace section computed by `pace-report.py` from git and the launcher's and the guard's records, its started cell and lift column (cause 3).
