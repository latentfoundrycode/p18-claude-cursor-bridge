# BUG-010-r1 report

## Summary

`CheckArgumentParser.error` now writes the usage-error line only when `sys.stderr` is not `None` and flushes standard output only when `sys.stdout` is not `None`, so a usage error still exits 2 with `RESULT: not checked` and the escaped error line when those streams exist, and skips the call that would raise `AttributeError` when a standard stream was closed at start.

## How the change addresses the named cause

The method no longer calls `write` on `sys.stderr` or `flush` on `sys.stdout` when that stream is `None`, which is Python's state for a standard stream the program was started without, so the AttributeError that turned a usage error into exit 1 no longer occurs.
