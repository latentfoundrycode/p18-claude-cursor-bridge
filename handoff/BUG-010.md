# BUG-010: workflow-check's usage error with a standard stream closed ends with exit 1

## Objective
Fix the following confirmed defect — repair the named cause, nothing else.

**Root cause (one sentence):** `CheckArgumentParser.error` in `bridge/cursor-bridge/workflow-check.py` (lines 752-758) calls `sys.stderr.write(...)` and `sys.stdout.flush()` without allowing either stream to be `None`, which is Python's state for a standard stream the program was started without, so the resulting AttributeError ends a usage error with exit 1 instead of exit 2.

**Evidence (copied from `docs/debug/BUG-010.md`):** "Hypothesis 1 holds. The traceback names `flush`. The stderr-closed run prints the usage line and no RESULT line. The root runs with the same streams closed are correct, which rules out hypothesis 2. `print()` to a `None` standard output does nothing in Python, so the only failing calls are the explicit `sys.stderr.write(...)` and `sys.stdout.flush()`." The symptom, as reproduced: with standard output closed, `python bridge/cursor-bridge/workflow-check.py --bogus` gives exit 1 and a traceback ending `AttributeError: 'NoneType' object has no attribute 'flush'`; with standard error closed it gives exit 1 and no `RESULT: not checked` (the usage line lands on standard output, because argparse's own `print_usage` falls back to it).

**Reproduction tests** (supervisor-written and committed; do not edit them), both failing today with exit 1:
- `tests/test_workflow_check.py::test_r014_usage_error_with_a_closed_stream_exits_2_without_traceback[stdout-closed]`
- `tests/test_workflow_check.py::test_r014_usage_error_with_a_closed_stream_exits_2_without_traceback[stderr-closed]`

The required behaviour is the usage error's, whichever stream is closed: exit 2; no traceback; `RESULT: not checked` as standard output's last line where standard output is open; `workflow-check.py: error: <message>` (the message passed through `escape_field`, as now) as standard error's last line where standard error is open.

## Context
- The method as it stands (`bridge/cursor-bridge/workflow-check.py`, lines 752-758):
  ```python
  class CheckArgumentParser(argparse.ArgumentParser):
      def error(self, message):
          self.print_usage(sys.stderr)
          sys.stderr.write("%s: error: %s\n" % (self.prog, escape_field(message)))
          print("RESULT: not checked")
          sys.stdout.flush()
          self.exit(2)
  ```
- When a process is started with file descriptor 1 or 2 closed, Python sets `sys.stdout` or `sys.stderr` to `None`. `print()` to a `None` standard output writes nothing and raises nothing; argparse's `print_usage` and `exit` already tolerate a `None` stream. The only calls that fail are the explicit `sys.stderr.write(...)` and `sys.stdout.flush()`.

A precondition in the test confirms the child really starts with the stream closed.

## Requirements
1. With standard output closed (`sys.stdout is None`), a usage error exits 2 with no traceback, and standard error's last line is `workflow-check.py: error: <message>`, the message escaped by `escape_field` as now.
2. With standard error closed (`sys.stderr is None`), a usage error exits 2 with no traceback, and standard output's last line is `RESULT: not checked`.
3. With both streams open, the output and exit code of a usage error are byte-for-byte what they are today: the usage line on standard error, then the error line on standard error, `RESULT: not checked` on standard output, standard output flushed, exit 2.
4. The repair is a guard that skips the write to standard error when `sys.stderr` is `None` and the flush of standard output when `sys.stdout` is `None`. This guard is the legitimate repair, not symptom suppression: `None` is the closed-stream state itself, not a wrong value standing in for a right one, and skipping a write or a flush to a stream that does not exist is exactly the behaviour wanted. It is the only kind of change permitted: no catching of `AttributeError`, `OSError` or exceptions in general; no change of exit code anywhere; no write redirected by the program's own code to the other stream or anywhere else; no replacement of a `None` stream by an object (such as `os.devnull`).
