# BUG-001: The Socket API key is in the environment while npm installs the Socket CLI

## Objective
Fix the following confirmed defect — repair the named cause, nothing else.

**Root cause (one sentence):** in `.github/workflows/tests.yml`, job `security-floor`, the step `Socket` puts the Socket API key into its step-level `env`, and a step-level `env` applies to every line of the step, so the key is in the environment while `npm install -g @socketsecurity/cli@1.7.0` installs the CLI and its unpinned transitive dependencies, whose lifecycle scripts could read it.

**Evidence** (found by the stage B1 review, both reviewers, 2026-10-16; cause proven by reading the file; `.github/workflows/tests.yml` lines 78-84 as they stand today):

```yaml
      - name: Socket
        env:
          SOCKET_CLI_API_TOKEN: ${{ secrets.SOCKET_SECURITY_API_KEY }}
          SOCKET_CLI_ORG_SLUG: ${{ vars.SOCKET_ORG_SLUG }}
        run: |
          npm install -g @socketsecurity/cli@1.7.0
          socket ci --no-banner
```

This contradicts TASK-002's own constraint: no secret on a scanner's path beyond its own token. (There is no `docs/debug/BUG-001.md` for this defect; the evidence above is the whole of it.)

**Reproduction tests** (supervisor-written and committed; both fail today and must pass after your change):
- `tests/test_release_b_ci_floor.py::test_r002_each_scanner_decides_its_step` — the step that holds the Socket key runs only `socket ci --no-banner`.
- `tests/test_release_b_ci_floor.py::test_r002_no_install_runs_beside_a_secret` — no step holding a secret installs or fetches anything; every `npm install` carries `--ignore-scripts`; the Socket CLI is installed at a pinned version in a step of the same job before the scan.

Satisfies: R-002 — The security floor (Semgrep, OSV-Scanner, Socket) runs in the bridge's own CI gate, pinned by commit, installing from a committed lockfile, alongside the tests it already runs.
