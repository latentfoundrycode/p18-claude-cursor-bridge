# BUG-002-r1 report

## Summary

`check_head` still splits the Workflows head on `→` and strips each segment and comma-split name for the open-list lookups, and it still returns before the shape test when the counts are not right. Once the counts are right, the shape test now requires `head` as received to equal the product type's Workflow name, or that name, one space, U+2192, one space, and the sub-type's Sub-workflow name. A mismatch still appends the existing `form` finding once. The six `test_r015_separators_are_exact` cases that passed before now fail the check, the two exact-separator controls still pass, and the rest of the suite stays green.

## How the change addresses the named cause

The shape test no longer compares stripped names with the open list; it compares the unstripped head text with the exact grammar string, so spacing the grammar does not allow is not normalized away before the verdict.
