## Summary

When the installed bridge and the release folder share a version string, `install()` now compares their manifests through `fingerprints_of` before printing the install banner or calling `replace_release`. If the file sets or fingerprints differ and `--anyway` is absent, the install exits 2 with a single refusal sentence and leaves the target untouched, so a same-version tree with different files can no longer replace the installed release without keeping the way back. Equal manifests and `--anyway` behave as before. The module docstring item 1 documents the rule; stamp and CLI reference were regenerated.

## Refusal sentence (as printed)

For the reproduction scenario in `tests/test_bug034.py` (one differing path):

`bridge-install: the release folder carries version 2026.01.01a, the release installed now, but not its files (1 file(s): cursor-bridge/old-only.md); a release with other files is stamped with a new version before it is installed, so that the release installed now is kept as the way back; nothing was changed; --anyway installs regardless (the maintainer's rehearsals).`

## How this addresses the named cause

The defect was that `save_previous` and the S4 check ran only when `old_version != new_version`, so a same-version install with a different manifest skipped the way back entirely. The new check runs for equal versions before any target mutation and refuses unless `--anyway`, closing that gap without changing `save_previous`, `replace_release`, or `rollback`.
