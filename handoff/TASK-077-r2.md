**Ruling 1. Every failed run of the window is read.** For every completed run of the window whose conclusion is `failure`, read its jobs, then each failed job's log. Any run of the window whose exit line reads `exit 1` is a finding. It becomes the standing finding (the newest such run's id) unless a run of the window created later than it ended `success`. The week's own kind is classified from the window's last completed run as before (green / scanner failure / no completed run). A finding found in the window, or standing from before, is reported beside that kind, not instead of it. **Ruling 2. A standing finding never cuts the classification short.** The week's runs are classified and read first, jobs and logs of failed runs included. Then the standing line is written beside the week's kind. `last_run_read` moves to the newest completed run of the window whenever the window completed any run, whatever the kind. Fault: `classify_window_runs` lines 618-619 return `"finding"` as soon as a finding stands and no run succeeded, before any classification, with `advance_last` False. **Ruling 3. Clearing a standing finding.** The standing finding is cleared when any run of the window, created later than the standing run, ended `success`, even if that success is not the last completed run. R6. **The kinds**, as step 1b and the design define them:

- **scanner failure**: the window's last completed run is a `failure` with another exit code or no exit line, or ended with any conclusion other than `success` and `failure`. The remedy is exactly `gh workflow run dependency-scan.yml --repo OWNER/REPO`.
- **no completed run**: the workflow is disabled (remedy `gh workflow enable dependency-scan.yml --repo OWNER/REPO`, then the rerun command); or no run of the window is listed (remedy: the rerun command); or only runs queued or in progress (no remedy: the next Sunday reads them).
