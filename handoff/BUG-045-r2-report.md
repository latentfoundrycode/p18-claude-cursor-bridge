## Summary

The permission guard now reads git's global options from a known list and refuses any other dash word before the subcommand as unreadable, and it refuses an alias defined in the command whose value's first word is a hook-skipping subcommand other than push. Round 1's lone-help exemption is unchanged. The new cases sit below round 1's builder cases in `tests/test_bug045.py`.

## Causes

An unknown git global option no longer hides the subcommand: `git_subcommand` reports a dash word outside the known list as unreadable instead of skipping it, the git branch of `_check_word_list` refuses that command with `_cannot` naming the option, and `state_changing` returns True for it.
An alias defined in the command for a hook-skipping subcommand no longer passes: the alias reading refuses a value whose first word is `commit`, `merge`, `rebase`, `am`, `cherry-pick` or `revert`, with the existing alias refusal text, while `push` keeps the forced-push test it already had.
