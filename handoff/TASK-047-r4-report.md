## Summary

Round 4 fixes `_load_bridge_env` in `conformance-check.py` so it resolves `bridge_env.py` from the directory of `os.path.realpath(__file__)`, matching the existing pattern used to load `workflow-check.py`, so a run through a symbolic link loads the real `bridge_env` module (with `status_workflow_line` and `status_values`) instead of falling back to the stand-in beside the link.

## Cause

`_load_bridge_env` built `bridge_env.py` from `HERE` (`abspath(__file__)`), which is the link's folder when the script is executed through a symlink; the stand-in module then lacked the status-header helpers and broke the Workflows line check in CI.
