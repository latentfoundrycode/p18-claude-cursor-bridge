## Summary

Round 2 makes the GitHub reader in `bridge_env.py` treat a rules reply it does not recognise as cannot read, read the rules endpoint a hundred rules a page until a short page, keep a check that is not completed after every completed one in every order, refuse a head whose rank fields cannot be read, and treat a time with no zone as no time. A head sha and a pull request number are checked before any call, the conformance none row names the branch instead of claiming that protection exists, and `_gh_get`'s docstring matches the tuple it returns.

## G1 to G8

- G1. `_rules_contexts` (3973-4002) returns cannot read when a rule is not an object, when `type` is missing or not a string, or when a `required_status_checks` rule has no `parameters` object or no list `required_status_checks`, and still skips every other string type.
- G2. `branch_rule` (4024-4037) reads the rules through `_page_path` from page 1 until a page holds fewer than 100 rules, returns cannot read for a page that is not a success or not a JSON list, and returns cannot read when page `_GH_MAX_PAGES` is still full.
- G3. `_last_by` (4212-4235) puts the not-completed rank first in every `started_at` key, chooses the id-only order from the completed members only, and orders the not-completed members by id then position.
- G4. `head_state` (4154-4156) calls `_rank_reason` (4189-4209), which answers cannot read naming `run_number`, `run_attempt` or `id` for a workflow run, `id` for a check run, or `updated_at` for a commit status, when that field cannot be read.
- G5. `_parse_time` (4176-4186) returns None when `fromisoformat` cannot read the string and when the result has no `tzinfo`, so `latest_of_each` never compares a naive datetime with an aware one.
- G6. `head_state` (4140-4142) answers cannot read from source `checks` and makes no call unless `sha` is 40 or 64 lowercase hexadecimal digits, and `pull_refs` (4069-4072) answers cannot read and makes no call unless `number` is a non-bool int of 1 or more or a string of ASCII digits only.
- G7. The none row in `conformance-check.py` (933) is `no required status check on <branch>; N6 needs the gate job required`, with the branch's name, and the verdict stays MISSING.
- G8. `_gh_get`'s docstring (3888) now states the return `(True, "", body)` or `(False, reason, body or None)`; the call is unchanged.

## Defects

1. `_rules_contexts` no longer skips a `required_status_checks` rule whose `parameters` or `required_status_checks` list is missing, null or not a list, and no longer skips a rule whose `type` is missing or not a string, so those replies are cannot read from the rules instead of none.
2. `branch_rule` no longer reads the rules with one call: it asks with `per_page=100` and `page=<n>` until a short page, so a required check on a later page is kept and a page that cannot be read is cannot read.
3. `_last_by` keeps the not-completed rank as the first part of every check key, including the id-only key, and decides that id-only fallback from the completed members only, so a pending check is not ranked below a completed one by id.
4. `head_state` refuses the head when a workflow run lacks an integer `run_number`, `run_attempt` or `id`, a check run lacks an integer `id`, or a commit status lacks an `updated_at` that `_parse_time` reads, instead of letting `latest_of_each` rank that entry below a well-formed older one.
5. `_parse_time` returns None for a time with no zone, so a naive datetime is never placed in an ordering key beside an aware one and `latest_of_each` raises no `TypeError`.
