# TASK-032: The code-review ceiling held by the launcher and the guard

## Objective
The bridge's code gate gets a round ceiling that programs hold, the way the design critique's ceiling is already held by the launcher (KP-062: a ceiling only the text holds stops nothing). A round is one version of an increment the gate's reviewers read: each builder run of a brief (`handoff/<ID>.md`, then `handoff/<ID>-r<N>.md`, a new numbered brief for every re-delegation, never a revision in place) and each Review B read that `review-guard.py snapshot <ID>-r<N>` opens, spent when its reply arrived. Above three rounds, the launcher (`bridge-run.py`) refuses a builder launch and the guard (`review-guard.py`) refuses a snapshot, unless a `Blocking class:` line (in the brief for the launcher, in `run/review/SCOPE-<ID>.md` for the guard) lifts that one round, or the owner's `Review rounds above the ceiling:` line in `docs/RUN_PARAMETERS.md` lifts the increment to a number of rounds. Both programs count a branch's rounds by one rule, read from both their records, so that renaming a brief or a snapshot, revising a brief in place, using a new ID for a fix brief, or starting `cursor-agent` outside the launcher (which `permission-guard.py` refuses) cannot get around the count. The one copy of the number, the five classes, the name grammar, the line readers and the squash-subject reader live in `bridge_env.py`. The launcher and the guard import them now, and TASK-033's `pace-report.py` and `plan-check.py` will import them later.

Satisfies: R-042: "The code gate has a round ceiling held by programs, as the design critique has (KP-062)." The full text is the R-042 row of `docs/REQUIREMENTS.md` (line 48). Read it whole before you start: it defines a round, the five blocking classes, the two lifts, the branch rule, the three evasions each program refuses, and the stage-review bound. The ceiling's number, three, is the owner's.
