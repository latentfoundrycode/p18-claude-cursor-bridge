## Summary

The permission guard now refuses every git word that begins with `alias.` and holds `=`, reads a long refused option by any prefix git's abbreviation rule would use, and lets `git config` name `core.hooksPath` only in the three read forms and the one write `core.hooksPath .githooks`. Round 1's lone-help line and round 2's known global-option lists are unchanged. Two PowerShell cases, `alias-value-in-double-quotes` and `alias-value-partly-quoted`, are still refused before that alias check, as a literal double quote, so their reason does not contain `alias`; the PowerShell reader is outside this round's scope.

## Causes

An alias defined in the command is no longer decided by its key's characters or its first raw word: the git branch refuses the word when it begins with `alias.` in any case and holds `=`, and it does not read the key or the value.
A refused long option is no longer read only as a whole word: `hook_skipper_option` reads a prefix of `--no-verify` of at least 6 characters as `--no-verify`, and `force_push_reason` reads a part before `=` that is a prefix of `--force`, `--force-with-lease`, `--force-if-includes` or `--mirror` and at least 4 characters as that option.
A `git config` that names `core.hooksPath` is no longer passed because some other word begins with `--get`, or because the value is relative: the words after `config` pass only in the four forms F8 lists.

## F6

The alias loop in the git branch of `_check_word_list` (lines 2276-2280) refuses a word whose first six characters are `alias.` in any case and which holds `=`, with the existing text `a git alias that defines a refused command (%s)` cut at 60 characters, and it still runs before `git_subcommand`. The old value-reading helpers `_alias_key_char`, `_alias_value_prefix` and `_alias_names_refused`, and the constant `_ALIAS_PREFIXES`, are removed; none had another caller, and the check does not use them.

## F7

`hook_skipper_option` (lines 2337-2357) returns a word of at least 6 characters that is a prefix of `--no-verify` in the same place and under the same `not snapshot` exemption as the full word (line 2352); the refusal text is unchanged and names the word as written. `force_push_reason` (lines 2409-2423) keeps the existing whole-word text and the existing `--force` abbreviation text, and also refuses when the part before `=` is at least 4 characters and a prefix of `--force`, `--force-with-lease`, `--force-if-includes` or `--mirror` (lines 2416-2418), with `git push with` plus the word. Short flags and a forcing `+` refspec are unchanged.

## F8

The `git config` refusal in the git branch of `_check_word_list` (lines 2287-2292) still keys on a word equal to `core.hooksPath` in any case, and it passes only when the words after `config` are exactly `core.hooksPath`, `--get core.hooksPath`, `get core.hooksPath`, or `core.hooksPath` followed by the value `.githooks` (the key in any case). Every other such command returns the existing text `git config core.hooksPath %s (the checks a commit runs are switched off; rule 4)`.
