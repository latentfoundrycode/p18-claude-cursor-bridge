# FIX-003: the session-start hook hardened before the first pointer line

## Objective
Hardening fix to one program, the session-start hook `bridge/cursor-bridge/session-start.py`. It has to land before TASK-012 writes the first module pointer line (`Sub-files:` / `Variants:`). This is not a symptom-driven bug fix. Each change below is a lead recorded in `docs/HARDENING.md`, section "## Stage B3 — the core and phase-module split", subsection "### TASK-010 with TASK-015, the carve and the hook's module pointers (2026-10-20)", and the cause of each is already known from the code. There are three code changes and one docstring change. (1) Today the exception's type name is read after the stdout/stderr redirection has ended, so a type name whose reading prints writes into the hook's output. (2) Today a line from the checker's `file_lines` that is not an exact `str` is silently skipped, so a mismatched checker names nothing and says nothing; it must instead make the checker "unusable", with the existing one plain line. (3) Today each pointer path is right-stripped, against the docstring's grammar. (4) The module docstring is made to state what the code does. The supervisor has already written the tests, and they currently fail. Your job is to make them pass without changing anything else.

Satisfies: R-005 — The compaction/session-start hook names the current phase's module(s) to re-read after a compaction (one for most phases; planning and building map to two), plus the conditional-workflow files (type, sub-type, trait) that touch the current phase; it carries the Phase→module table for every template phase value, including the reflection and project-end modules and any further files the phase re-reads.

## Requirements
1. **R1. Read the exception's type name where the checker cannot print.** Two places build a `cannot be loaded (...)` or `cannot be used (...)` line from `safe_exc_type_name(err)`: `load_checker_module` and `pointers_part`'s `except BaseException` handler. At both, the call to `safe_exc_type_name` must run inside a redirection of `sys.stdout` and `sys.stderr` to a discarded `io.StringIO`, so that a type name whose reading prints writes nothing to the hook's output or error stream. If reading the name raises any exception, today's behaviour stays (`an exception`). A plain name is still printed as today. The simplest correct form is to put the redirection inside `safe_exc_type_name` itself.
2. **R2. A line that is not an exact str makes the checker unusable.** In `pointer_paths_from_module`, a line from `wc.file_lines(text)` whose type is not exactly `str` (`type(line) is not str`) is no longer skipped. It raises `TypeError` (any message). The existing handler in `pointers_part` then turns that into exactly `~/.claude/cursor-bridge/workflow-check.py: cannot be used (TypeError)`, naming no pointer-line file and no conditional file. This covers bytes lines, a `str` subclass, and a non-str fence line that would otherwise leave a fenced pointer line to be read. Keep the per-path `if type(p) is not str: continue` check.
3. **R3. Take a pointer path exactly as written between separators.** Remove the per-path right-strip (`p = part.rstrip()`). Only the line's end is stripped, which is the existing `rest = line[len(prefix):].rstrip()`. Match each part of `rest.split("; ")` against `POINTER_PATH` exactly as it is. A path followed by a space or a tab before its separator then fails the pattern and is not named.
4. **R4. Make the module docstring state what the code does.** Make exactly these three edits to the module docstring, and no other docstring change anywhere in the file:
   (a) replace "Each path, ignoring trailing whitespace on the line, must match" with "Each path is taken exactly as written between separators (only whitespace at the end of the line is ignored) and must match". Leave the pattern and the rest of that sentence unchanged.
   (b) replace "what the checker prints is discarded" with "what the checker prints through sys.stdout and sys.stderr is discarded".
   (c) add this sentence to the "Failing open" paragraph: "A line the checker's file_lines gives that is not an exact str makes the checker unusable (``cannot be used (TypeError)``)."
   The docstring stays ASCII-only.
5. **R5. Regenerate the stamps with their tools, never by hand, as the last step and in this order.** First `python tools/dump-cli.py`, after the last edit of session-start.py. R4 changes the rendered docstring, so `docs/cli-reference.json` and `docs/CLI_REFERENCE.md` are expected to change; then `python tools/dump-cli.py --check` must pass. Then `python tools/make-manifest.py`, after the last edit of any file under `bridge/`. Then `python bridge/cursor-bridge/bridge-check.py --root bridge --sources --quiet` must print a line containing `SOURCES MATCH`. If you edit session-start.py again after any of these, run all three again in the same order.
