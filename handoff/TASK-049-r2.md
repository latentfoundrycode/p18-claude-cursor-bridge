**What the increment is (unchanged).** Release B2 gives the four tabular records (`docs/INVENTORY.md`, `docs/REQUIREMENTS.md`, `docs/diagrams/INDEX.md`, `docs/diagrams/DEVIATIONS.md`) a YAML front-matter header that declares the table's shape, never its rows. Every program that reads one of them reads the header first through `bridge_env`, splits each row by the declared columns and reads it by role; each table's one owning checker compares the declared shape with the table and prints `HEADER DISAGREES: <key>`; a file with no header is read through the one prose reading per record kept in `bridge_env`, unchanged in rule. The aim: each table has one reader, one owner and one shape, so two programs can never read the same row two ways.

**The root cause (confirmed, common to the findings).** Round 1 added a header path beside each header-less path instead of one reading per record: the header paths dropped rules the header-less paths enforce (B1, B2, B3), kept a header-less check inside the header path (B4), and left the old copies of the readings in the programs beside the moved ones in `bridge_env` (should-fix 1). Where `bridge_env` cannot be used, two programs either crash or give a verdict on nothing (should-fix 3 and 4), and one reader swallows a `HeaderError` (should-fix 2). The fix: with a header that agrees, each program reads the same rows by the same rules as without one, from one copy of each reading; the header only says where each column stands.

Satisfies: R-060 - The tabular records' headers declare the table's shape, never its rows: `docs/INVENTORY.md` carries `record: inventory` with `reflected_through`, `development_data` and `tables` (the four sections, each its `columns` and `key`), read first by `inventory-check.py` and `conformance-check.py`; `docs/REQUIREMENTS.md` carries `record: requirements` with `columns`, `roles` (`id`, `status`, `evidence`) and `statuses`, read first by `completion-check.py`, its owning checker, and `diagram-check.py` (the R-ids traced read from the id column); `docs/diagrams/INDEX.md` carries `record: diagram-index` with `columns` and `roles` (every column), read first by `diagram-check.py`, its owning checker, and `plan-check.py`; `docs/diagrams/DEVIATIONS.md` carries `record: deviations` with `columns` and `roles`, read first by `diagram-check.py`, its owning checker; each program splits a row by the declared columns; each table's owning checker compares the declared shape with the table and fails a difference, the other reader trusting that check; each keeps the one fallback `bridge_env` holds for a file with no header, tested on a header-less record, and refuses a malformed header as R-058 says.
