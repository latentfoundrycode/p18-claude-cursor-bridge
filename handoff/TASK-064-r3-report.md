## Summary

`head_state` now refuses a workflow run, check run, or commit status whose grouping or ranking field is not of its type, through the same `_rank_reason` check round 2 used for rank fields. A missing key, a null, a bool, or a value of another type on `workflow_id`, `event`, `check_suite_id`, a check's `name`, `check_suite.id`, or `app.id`, or a status's `context` or `id`, is cannot read, so `latest_of_each` never groups that entry under an empty or wrong key.

## H1

H1. `_rank_reason` (4189-4226) returns a reason naming the field when a workflow run lacks an integer `id`, `run_number`, `run_attempt`, `workflow_id`, or `check_suite_id`, or a non-empty string `event`; when a check run lacks an integer `id`, a non-empty string `name`, a `check_suite` object with an integer `id`, or an `app` object with an integer `id`; and when a commit status lacks an `updated_at` that `_parse_time` reads, a non-empty string `context`, or an integer `id`; a non-object entry keeps round 2's reason, and `head_state` (4154-4156) is unchanged and still answers cannot read with that reason and that list as `source`.
That is the named cause: a run with no `workflow_id`, a check with no `name` or with a `check_suite` or `app` whose `id` is not an integer, and a status with no `context` or no integer `id`, are cannot read in `head_state` before `latest_of_each` can group them under an empty or wrong key and drop a newer failure.
