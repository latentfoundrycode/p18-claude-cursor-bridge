# TASK-071 round 1 report

## Summary

`records-migrate.py` now refuses a header-less run-parameters record when `run_parameters_fallback` leaves any of the five values empty, printing one `cannot read` line for the first empty label and writing nothing, and `inventory-check.py` fails a run-parameters file, headed or not, that has any of those five empty. Both programs call one new `bridge_env` helper that names the empty values from `_RUN_PARAM_VALUE_PREFIXES`. The fallback itself is unchanged, so a heading, a bullet, or a bold line is still an empty value.

## Files changed or created

- `bridge/cursor-bridge/bridge_env.py` (modified): added `empty_run_parameters`.
- `bridge/cursor-bridge/records-migrate.py` (modified): the run-parameters composer returns a refusal when any of the five is empty.
- `bridge/cursor-bridge/inventory-check.py` (modified): empty values are failures, and the helper's name is on the bridge_env guard list.
- `bridge/cursor-bridge/MANIFEST.json` (modified): regenerated by `python tools/make-manifest.py`. Step 11's `git status --short` lists it and does not list `bridge/cursor-bridge/VERSION`.

## What meets R1-R7

R1. The refusal is in `compose_header`, not in `main`. `_compose_run_parameters_header` (`records-migrate.py` lines 446-456) calls `empty_run_parameters` on `run_parameters_fallback` and, when that list is not empty, returns `(None, "<label> has no value on a plain line")` using the first pair's label. `compose_header` (lines 482-483) returns that pair for kind `run-parameters`. `main` (lines 751-757) already prints `cannot read <shown>: <reason>` and continues, so `_write_record` is never called, no temporary file is created, and neither `would write` nor `wrote` is printed. A `cannot read` still does not change the exit. This is the same `(None, reason)` path the other kinds use, so there is one printer and the check and the run share it. A record with all five values still returns `(header, None)` and migrates as before. A record that already has a header is skipped at lines 717-723, before `compose_header`.

R2. In `inventory-check.py` `main`, after a valid header, lines 353-354 append `RUN PARAMETERS: <key> is empty` for each empty header key, after the existing `HEADER DISAGREES` loop (lines 351-352). With no header, lines 355-358 append `RUN PARAMETERS: <label> is empty` for each value the fallback leaves empty. Both go into `fails`, so they count in `RESULT` and the exit is 1. A malformed header still prints `HEADER MALFORMED` and returns 2 at lines 339-343 or 346-349, before either loop. A missing `RUN_PARAMETERS.md` never enters the block (line 330). The new check is item 7 of the module docstring (lines 27-30).

R3. The helper is `empty_run_parameters(values)` in `bridge_env.py` lines 3136-3147. It returns a list of `(key, label)` for each of the five prefixes whose value is exactly `""`, in `_RUN_PARAM_VALUE_PREFIXES` order. The label is that prefix without its last two characters (the trailing colon and space). `records-migrate.py` calls it at line 448. `inventory-check.py` calls it at lines 353 and 356-357, and lists the name in `_INVENTORY_BRIDGE_NAMES` at line 88. No other line of `bridge_env.py` changed. `run_parameters_fallback` is the function that ends at line 3133, byte for byte as before.

R4. No new prose form is read. A `##` heading, a bullet, and a bold line still produce `""` from the unchanged fallback, so the migration refuses them and the inventory check fails them. The acceptance cases for the heading, bullet, and bold forms cover that.

R5. `_write_record` was not edited. The two exit-3 acceptance cases are in the Done pytest for `tests/test_program_run_parameters_empty.py`. Their results are in that command's output below.

R6. No option, configuration key, environment variable, or dependency was added. `build_parser` in both programs is unchanged. The inventory-check module docstring names the new failure as check 7 (lines 27-30). `python tools/dump-cli.py --check` is command 7 below.

R7. The fixture is `tests/fixtures/headers/field/run-parameters.md` (a subfolder, so it does not match `tests/fixtures/headers/*.md`). It is header-less: a title, a `Set:` line, then each of the five labels as a `##` heading with the value on the next line. The case that reads it is `test_r091_the_field_form_fixture_is_refused_naming_stage_pause` in `tests/test_records_migrate.py` lines 1668-1684, below the builder marker at line 1458.
