### Pointer lines in a module (this increment defines the grammar)
4. A pointer line is a line of an installed module file (`~/.claude/cursor-bridge/workflow/phases/<key>.md`, read as UTF-8 with the BOM dropped) that meets all of these:
   - it stands outside fenced blocks, with fences read as `workflow-check.py` reads them (`opening_fence` / `closing_fence`; an unclosed fence runs to the end of the file);
   - it begins at column 0 with exactly `Sub-files: ` or `Variants: `;
   - after that prefix come one or more paths separated by `; `.

   Each path, ignoring trailing whitespace on the line, must match `^[a-z0-9-]+(/[a-z0-9-]+)*\.md$`. That is a path relative to `workflow/phases/`, made of lower-case letters, digits, hyphens and `/`, ending `.md`, with no empty, `.` or `..` segment, no drive and no leading `/`. Any other path on the line is ignored, and the line's valid paths still count.

   The named files are listed right after their module, in the order written, with `Sub-files:` and `Variants:` lines taken together in file order. A path already printed is not printed again. These files are named without checking that they exist. A module file that is missing or cannot be read contributes no pointer line and is still named.

   State this grammar in the docstring, because TASK-012 and TASK-013 will write the first real pointer lines against it.

### Conditional files
5. For each `Workflows:` line of the status file, in file order (a line that starts with exactly `Workflows: `):
   - (a) Drop an optional `<part>: ` prefix, the text before the first `: ` in the part of the line before `; traits: `. It is allowed whatever the number of lines.
   - (b) If what is left is `not yet classified`, or it does not contain `; traits: ` exactly once, the line contributes nothing. A status file with no `Workflows:` line contributes nothing.
   - (c) Otherwise the head names the type by its Workflow name, optionally followed by ` → ` and the sub-type's Sub-workflow name. The traits are separated by `, `, or the traits text is `none`.
   - (d) Map each name to its key through the installed open list's tables: Workflow name to the type's `Key`; Sub-workflow name to the sub-type's `Key`; trait `Name` to the trait's `Key`. A name the open list does not have contributes no file, and the line's other names still count.
   - (e) The line's candidates are, in this order: `types/<type key>.md`; then `types/<type key>/<sub key>.md` when a sub-type is named; then `traits/<trait key>.md` for the line's traits, sorted by the open list's trait order (`trait_order`) whatever order the line writes them in. This is R-034's order.

   A candidate is named only if all of these hold:
   - it exists under `~/.claude/cursor-bridge/workflow/` as a regular file;
   - it is not a link (`is_link`);
   - it can be read as UTF-8;
   - it touches the phase: among `heading_spans(text)`'s headings, read with `parse_heading`, there is an `add` or `set` whose target's module (the part before the first `.`) is one of the phase's module keys, or a `replace` whose target is one of them. A heading inside a fenced block never counts. `heading_spans` already leaves fenced headings out.

   A file already named for an earlier line (an earlier part) is not named again.
6. An unwritten workflow named on the line (no file) names nothing. The project still gets its modules and conventions.
