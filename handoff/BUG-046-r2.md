# BUG-046 round 2: the merge endpoint read after every escape is decoded and only from the path (R-082)

Round cause: security

## Objective
Fix the following confirmed defects in the permission guard's `gh api` refusals, and nothing else.

This is round 2 of BUG-046. Round 1 made the two ruled refusals (a body the guard cannot read, whatever the endpoint; the merge endpoint, whatever the method), and all of that stays except what G1 to G5 below change. The supervisor, Review A and the security audit of round 1 found two defects in the merge-endpoint rule round 1's brief gave, both the brief's own error, not the builder's. The supervisor commits round 1's tree together with this brief and the new tests before your run, so the line numbers below hold when you start.

**The confirmed defects** (each reproduced in process on round 1's tree, each now a red test):
1. `bridge/cursor-bridge/permission-guard.py:2338` resolves dot segments with `posixpath.normpath` over the **whole** word, query and fragment included, so a `..` after a `?` or `#`, or a trailing `merge/..`, removes the merge path gh requests: `gh api -X PUT 'repos/o/r/pulls/5/merge?a=/../../x'`, `...merge#/../../x`, `...merge/..`, `...merge/%2e%2e`, `...merge/.%2e` pass under both tools. Commit f3fa7b4's guard refused each: a regression this round must undo.
2. The same line decodes only `%2f` and `%2e`. gh sends a path's percent-escapes as written (Go's `net/url` keeps a valid raw path), and an escaped letter is the same path as the letter (RFC 3986, 6.2.2.2): `gh api -X PUT repos/o/r/%70ulls/5/merge`, `.../pulls/5/merg%65`, `.../me%72ge`, and every letter escaped pass under both tools.
3. An advisory of the security audit, the same family, taken here: the merge-mutation refusal at 2328 looks for the mutation's name in the raw words, so a name with an escaped letter in a URL query string (`gh api -X POST 'graphql?query=mutation%7Bmerge%50ullRequest(...)...'`) passes.

**Two test findings of Review A** on round 1's own cases below the marker: the PowerShell rows of `rest-glued-field` and `graphql-glued-field` are refused by another rule (a switch split at a dot), so asserting only `refused` proves nothing about F1 there; and the id `percent-2e-parent` names a single-dot segment, not a parent.

**The reproduction tests:** `tests/test_bug046.py`, the section headed `# ---------------------------------------------------------------- round 1's findings (the supervisor, Review A and the security audit, 2026-11-17)`, above the builder's marker. On round 1's tree the result is quoted under Constraints, "Known failures"; every case in the file must pass.
