# BUG-003: workflow-check prints non-ASCII bytes, and skips a `types` or `traits` path that is a file

## Objective
Fix the following two confirmed defects in `bridge/cursor-bridge/workflow-check.py` — repair each named cause, nothing else.

**Defect 1 — root cause (one sentence):** `escape_field` (line 129) keeps every character for which `str.isprintable()` is true, including non-ASCII ones such as `é` and `→`, so the bytes a finding line carries depend on the console's encoding: under cp1252 `é` leaves as the raw byte 0xE9 (which a UTF-8 reader cannot decode) and `→` as `→` (through the `errors="backslashreplace"` the `__main__` block sets), under UTF-8 both leave as raw multi-byte sequences.

**Evidence (defect 1):** a status file whose line is `Workflows: Tést Development; traits: none`, checked with `--open-list tests/fixtures/workflows/status/open-list.md --status <file>` on Windows, printed `FAIL (unknown) <file>: T\xe9st Development - name is not in the open list` with the byte 0xE9 raw in standard output (found by Review B at stage B2's review, round 2; reproduced by the supervisor). The two sibling programs already print ASCII: `inventory-check.py` (line 191) and `conformance-check.py` (line 300) pass every field through `ascii_text(mod.escape_field(value))`, where `ascii_text` is `.encode("ascii", "backslashreplace").decode("ascii")`; so the bridge's own convention is ASCII output, and only `workflow-check.py` run on its own breaks it.

**Defect 2 — root cause (one sentence):** in `collect` (line 288), a layer path (`<root>/types` or `<root>/traits`) that exists but is not a folder reaches `if not os.path.isdir(base): continue` (about line 319) and is skipped silently, as if the layer were missing, so a malformed root passes with `RESULT: OK`.

**Evidence (defect 2):** a root holding a regular file named `types` gives exit 0 and `RESULT: OK` (Review B, reproduced by the supervisor). A layer path that is a link is already reported, through `found.append((layer, "link"))` and the `form-path` action, as `FAIL (form) <root>/types: types - path is not a conditional-workflow file`; a layer path that is a file must be reported by that same line.

**Reproduction tests** (supervisor-written and committed; do not edit them):
- `tests/test_workflow_check.py::test_r014_output_is_ascii_on_every_console` — 2 cases (`utf-8`, `cp1252`), both failing today; each must pass.
- `tests/test_workflow_check.py::test_r014_layer_path_that_is_a_file_is_form` — failing today; must pass.
- `tests/test_workflow_check.py::test_r014_status_case_gives_exactly_its_findings[form-part-arrow.md]` — expects the arrow in a part name printed as `→`; it passes today on Windows only because the console cannot encode the arrow, and fails on Linux; after your change it passes everywhere.

Satisfies:
- R-014 — `workflow-check.py` verifies: every change targets an existing extension point; replace/set appears only in a type or sub-workflow and replace only on a replaceable phase; trait additions only add; every sub-workflow names an existing type workflow; every project's `Workflows:` line names, per part, exactly one product type, at most one sub-type of that type, and traits, all in the open list — an unwritten type or sub-type fails (pauses the project), an unwritten trait is flagged, non-fatal (§6.7).

## Context
- `escape_field(value)` today: printable characters stay; every other character becomes `\xNN` (code below 256), `\uNNNN` (up to 0xFFFF) or `\UNNNNNNNN`. Every field of a printed finding passes through it (paths, names, reasons' fields), and argparse's usage message too (test_r014_usage_error_message_is_escaped). The `__main__` block sets `errors="backslashreplace"` on standard output and standard error; keep it.
- The escape forms are the ones `str.encode("ascii", "backslashreplace")` produces, so after the change the sibling programs' `ascii_text(escape_field(v))` gives exactly what it gives today.
- `collect` records a layer link as `found.append((layer, "link"))`; the loop after the walk turns a `link` item into `{"rel": rel, "action": "form-path", "name": parts[-1]}`, printed as `FAIL (form) <root>/<layer>: <layer> - path is not a conditional-workflow file`. Items are sorted by `rel`, so `traits` is reported before `types`.
- A layer path that does not exist is skipped without a finding (the existing `FileNotFoundError` / `NotADirectoryError` branch) and stays skipped; a layer path that cannot be examined is an error (exit 2) and stays one; a link stays a link.
- Development data: the dev build is the Workspace sources under `bridge/`; never run anything against `~/.claude` or any installed bridge. This fix runs only the test suite and the read-only checks under Done, all inside the Workspace.
- Security context: the check's verdict gates intake and calibration; its output is read by the supervisor's session and by two programs that parse it. Output that depends on the console's encoding can fail a reader's decode or show a different line than another platform shows. The governing rules are in `bridge/cursor-bridge/secure-coding.snapshot.md`; the project records no ASVS level, so L1 applies: encode output for its reader, and fail closed on input of the wrong shape.

## Requirements
1. `escape_field` keeps a character only when it is printable and ASCII (code point below 128); every other character becomes `\xNN` (below 256), `\uNNNN` (up to 0xFFFF) or `\UNNNNNNNN`, lowercase hexadecimal, as today. Its docstring says so.
2. Every line `workflow-check.py` prints to standard output is ASCII, whatever the console's encoding.
3. In `collect`, a layer path that exists, is not a link and is not a folder is recorded so that it is reported exactly as a layer link is: `FAIL (form) <root>/<layer>: <layer> - path is not a conditional-workflow file`, and is not walked.
4. Nothing else changes: every other finding, every exit code, the order of findings, the existing escape forms of control characters (`\x1b`, `\x07`, ...).
