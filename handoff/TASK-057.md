# TASK-057: The trace check's move mode (R-077)

## Objective
The bridge's instruction texts are the `.md` files under `bridge/`. Today `bridge/cursor-bridge/trace-check.py` only traces passages from one pinned pre-split baseline commit (R-029, the "pinned mode"); a passage that a later pull request drops, rewords or moves out of `bridge/` passes unseen. This increment adds a second mode to the same program, `python trace-check.py --moves [--base <rev>]`, which compares the committed state of a range (the base to HEAD) and fails for every passage of a changed instruction file at the base that stands in no instruction file at HEAD, unless an entry that the range itself adds to the tracked record `docs/TRACE_MOVES.md` excuses it. CI runs it through a test on every pull request. The increment also puts `docs/TRACE_MOVES.md` on `review-guard.py premerge-records`' full-gate list, because a program reads that record to pass a check, and regenerates the command reference and the manifest. The pinned mode, its entries and its exit codes stay exactly as built.

Satisfies: R-077 - A moved or retired instruction passage is caught by a program (T-MOVE): `trace-check.py --moves [--base <rev>]` (the base always the merge-base of HEAD with the revision given, `origin/main` by default, the resolved commit named on the mode's first line) reads every `.md` file under `bridge/` but the CHANGELOG, as the place a passage leaves and the place it may go, and fails, naming file and first words and printing the entry line that would excuse it, for each passage of a changed file at the base that stands in no such file at HEAD, a reworded passage included, unless an entry of the tracked record `docs/TRACE_MOVES.md` excuses it, one passage per entry, by the hash of its normal form and its first words; the mode reads only the entries the range itself adds to that record, so an entry of an earlier pull request is never read again, and an added entry that matches no dropped passage of the range is itself a finding; a test runs the mode, CI's tests job fetching the full history on pull requests and the test passing the pull request's base branch as the base; `review-guard.py premerge-records` holds `docs/TRACE_MOVES.md` to the full gate; the pinned mode and its entries stay as built. (Full text: the register's row in `docs/REQUIREMENTS.md`; the design: the paragraph beginning `*T-MOVE.*` in `docs/DESIGN.md`.)

## Context
**The program as built** (`bridge/cursor-bridge/trace-check.py`, 894 lines). Reuse these; do not write a second version of any of them:
- `def parse_units(text):` returns `(units, headings_outside_fences)`; each unit is a dict with `"normal"` (its normal form), `"chain"` (the heading chain) and `"kind"` (`"para"`, `"table"` or `"fence"`). Headings are not units. The normal form of a paragraph, list item or table is `normal_form_paragraph` (lines stripped, joined, whitespace collapsed to single spaces); of a fenced block `normal_form_fence` (lines kept, each `rstrip`ped, joined by `\n`). This is "the normal form the pinned mode uses".
- `def escape_field(value):` escapes every character outside printable ASCII as `\xhh` (below 0x20, 0x7f, and 0x80 to 0xff), `\uhhhh` or `\Uhhhhhhhh`. Every field the program prints that comes from a repository (a path, a passage's words, a revision text) goes through it.
- `def git_run(root, args):` runs `["git", "-C", root, *args]` with `capture_output=True`, `stdin=subprocess.DEVNULL`, `timeout=GIT_TIMEOUT` (120 s) and `creationflags=getattr(subprocess, "CREATE_NO_WINDOW", 0)`; returns `(proc, None)` or `(None, reason)` on a timeout or a start failure.
- `def decode_git_bytes(data):` drops a UTF-8 byte-order mark, decodes UTF-8 (raises `UnicodeDecodeError`), and turns CRLF and CR into LF.
- `class CheckArgumentParser(argparse.ArgumentParser)` prints `ERROR: usage: <message>` and `RESULT: not checked` and exits 2 on a usage error. `build_parser()` today adds `--repo DIR` and `--map`.
- `main(argv=None)`: `--repo` gives the repository root (default: three folders up from the program file). Exit 2 cases print `ERROR: ...` lines then `RESULT: not checked`; exit 1 prints `RESULT: <n> problem(s)`; exit 0 prints `RESULT: OK`. The pinned mode needs `bridge/cursor-bridge/workflow/trace-baseline.txt`, `.../trace-exceptions.md` and `bridge/commands/supervisor.md`; the move mode needs none of them.
- The `if __name__ == "__main__":` block reconfigures stdout and stderr with `errors="backslashreplace"`; keep it.

**The acceptance tests** (`tests/test_program_trace_moves.py`, the supervisor's; read its module docstring and every test before you start). They build scratch git repositories under `tmp_path` (a `main` that is the base with `refs/remotes/origin/main` beside it, a branch `work` carrying the change) and run `python trace-check.py --moves --repo <scratch> [--base ...]`. What they pin, exactly:
1. **Entry line form.** `- <sha256 hex of the passage's normal form, UTF-8> <the normal form's first eight whitespace-separated words joined by single spaces, escaped by escape_field>`. An entry is therefore always ASCII.
2. **Excuse.** An entry excuses a passage only when both its hash and its first words equal the passage's (a reworded passage keeps its first words but changes its hash, and the entry made from the new wording excuses nothing). One passage per entry.
3. **First output line.** The mode's first output line holds the full 40-character id of the base it used: the merge-base of HEAD with `--base`'s revision, `origin/main` by default. A revision ahead of the branch therefore never makes main's later text read as dropped.
4. **A dropped passage.** It prints a line beginning `FAIL` naming the file (its repository path, forward slashes) and the passage's first words (escaped), and the output holds the entry line (form 1) that would excuse it.
5. **An unmatched entry.** An added entry that excuses no dropped passage of the range prints a line beginning `FAIL` holding its hash.
6. **Exit 1** with a `RESULT:` line other than `RESULT: OK` when anything failed.
7. **Exit 0** with `RESULT: OK` and the counts written as `<n> file(s) compared`, `<n> passage(s) compared` and `<n> excused` otherwise (the test reads each as `\b(\d+) <label>\b`). Test `test_r077_the_entry_the_range_adds_excuses_its_passage` expects `1 file(s) compared`, `3 passage(s) compared`, `1 excused` for one changed file of three passages (a heading is no passage).
8. **Exit 2**, with no `RESULT: OK`, for a base that cannot be read (its output naming the revision, e.g. `no-such-revision`) and for a `--base` value beginning with `-` (the test passes `--base=--output=x` and checks that no file `x` was written).
9. **`--moves` works with `--repo DIR`** and needs none of the pinned mode's files: the scratch repositories have no `trace-baseline.txt`, no `trace-exceptions.md` and no `supervisor.md`.
10. **The instruction files.** "Every `.md` file under `bridge/` but the CHANGELOG" means every tracked `.md` path under `bridge/` other than `bridge/cursor-bridge/CHANGELOG.md`, read from git at the base and at HEAD: committed state, never the working tree. It is both the place a passage leaves and the place it may go; a passage moved into the CHANGELOG is dropped.
11. **A changed file** is one whose content differs between the base and HEAD, a deleted file included, and a renamed file read as a deletion and an addition (so a renamed file's passages are found at its new path and pass). This must hold whatever the user's or the repository's git configuration says about rename detection.
12. **The entries read** are the lines of `docs/TRACE_MOVES.md` present at HEAD and added in the range (not present at the base), and only lines of the entry form; every other line is ignored. An entry an earlier pull request added (present at the base) is never read: it excuses nothing and fails nothing. A `docs/TRACE_MOVES.md` absent at the base means every entry line at HEAD is added; absent at HEAD means no entries.
13. **The passages compared** are the passage units, by `parse_units`, of the changed files at the base. A passage "stands" at HEAD when a unit with the same normal form is in any instruction file (item 10) at HEAD, changed or not.
14. **This repository's own history.** `test_r077_the_mode_passes_on_this_repository_s_own_history` runs the mode on this Workspace with `--base origin/<GITHUB_BASE_REF>` where that variable is set, the default base otherwise; it skips where the history is shallow or there is no `origin/main`. `docs/TRACE_MOVES.md` states the same form at its head (its sections "The form of an entry" and "Which entries are read"); where it and this list differ, stop and report it.
