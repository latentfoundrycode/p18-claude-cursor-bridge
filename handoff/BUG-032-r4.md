**The defect.** In `main`'s `--checkpoint` branch (`bridge/cursor-bridge/mutation-run.py`), the single-file runs add the conftest each reports to one shared set, `failed_conftests`, and the item loop blocks every item by `checkpoint_item_blocked_by_conftest(item, failed_conftests)`, the first conftest of that whole set on the item's way, not by what that item's own file's run reported. So when the run of one file reports a conftest that lies on a shared path (`tests/conftest.py`, a root `conftest.py`), every other file under it is listed `not run`, even a file whose own run and the joint run were clear; a new test passing on the old code then gives exit 0. The run of a file can report a shared conftest by a forged line from a failing conftest beside it, by the shared conftest failing only in a run that holds that file, or by a test module that lifts pytest's output capture, writes the line and exits 4. Reproduction: `tests/test_bug032.py::test_bug032_r4_a_clear_file_is_judged_beside_a_blocked_one[forged]`, `[argv]` and `[module]` (`tests/conftest.py`, added by the increment, is the shared parent of `tests/a/test_a.py`, passing on the old code, and `tests/b/test_b.py`: today both print `not run (tests/conftest.py)`, exit 0; `tests/b/test_b.py` must print its `not run` line and `tests/a/test_a.py::test_old: passing on old code`, exit 4). The fourteen earlier tests of the file (thirteen functions, round 3's forgery test parametrized twice; round 3's brief miscounted them as fifteen) must keep passing.

Satisfies: R-041, as `handoff/BUG-032.md`.
