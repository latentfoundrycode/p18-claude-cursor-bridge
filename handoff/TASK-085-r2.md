## Corrections
1. **R7's line holds the format text (defect; Review A B1).** The refusal for a module loaded from the Workspace is one line whose format text, as it stands in the source, contains `module from Workspace path %s was loaded` unbroken, the module's name and the rest following it, for example: `"mutation-run: module from Workspace path %s was loaded (module %s; an editable install of the project is the usual cause; use import_roots for a finder-style install)" % (place, mod)`. It still names the module, the place (its Workspace-relative path), an editable install as the usual cause and the `import_roots` key; it stays ASCII and one line. Delete the non-dict fallback (line 1570): the plugin writes dicts only, so a `loaded_ws` item that is not a dict with string `module` and `path` is refused by the same line with what it holds, never skipped and never a traceback.
2. **The mapped folder keeps its letter case and is measured against the real Workspace (defect; Review A B3 and should-fix; the tests `test_task085_mapped_folder_keeps_its_letter_case_for_the_dotted_name` and `test_task085_workspace_reached_through_a_link_still_maps_its_entries`).** In `map_probe_entries`, resolve both paths once, without changing their case: the Workspace as `wr = os.path.realpath(os.path.abspath(workspace))`, each entry as `ar = os.path.realpath(os.path.abspath(raw))`. Decide "inside the Workspace" by comparing `os.path.normcase(ar)` with `os.path.normcase(wr)` (equal, or the first starting with the second plus `os.sep`), and form the Workspace-relative folder from the unfolded paths, `os.path.relpath(ar, wr)`, with `/` as separator. A `ValueError` (different drives) or `OSError` from any of these skips that entry, never an exit of its own. So a path entry into `SDK/Src` maps to `SDK/Src`, the dotted prefix `SDK/Src/` matches the mutated file `SDK/Src/pkg/calc.py`, and a run started in the Workspace through a junction or symbolic link still maps an entry that names the Workspace's real folder. Keep the check that the mapped folder lies inside the copy.
3. **The generated plugin knows the Workspace by both its paths (defect; follows from correction 2).** Where the run is started through a link, `os.getcwd()` and the paths modules are loaded from may name the Workspace by its real folder. The plugin's two Workspace checks (a module loaded from the Workspace, R7; an entry of the import path that stands ahead of the copy, R8) treat a path as inside the Workspace where it lies under the Workspace as given or under its real folder (`os.path.realpath`), each compared by `os.path.normcase`; the copy likewise by its path as given or its real folder. The data enters the plugin as literals, as today. A module so found is reported with its Workspace-relative path, as the tracked list names it.
4. **The `import_roots` link check (defect; Review A should-fix).** In `validate_import_roots`: remove the call to `refuse_links_under` (a link inside the folder an entry names is not that entry's business; the copy's own link refusals cover the tracked files). Remove the `os.path.lexists` guard: the walk runs for every entry, from the Workspace root down through each component of the entry, and it fails closed: a component that is a symbolic link or a junction (`bridge_env.is_link`) refuses with the `link` line; a component that does not exist ends the walk (nothing below it can be a link); a component whose state cannot be read (an `OSError` other than the path not existing) refuses with the `link` line, never passes. The missing-folder and is-a-file refusals of the ordinary mode stay as round 1 wrote them.
5. **The probe imports nothing (defect; Review A should-fix).** The probe's code is `import sys; print(repr(sys.path))` (no other import: `sys` is built in, so nothing of the copy can stand in for it), and its output is parsed with `ast.literal_eval` (`ast` from the standard library, imported by the program), the result checked to be a list of strings. Every failure leaves the run on the copy's root alone, as R1 says: an `OSError` from starting the process, a timeout, a non-zero exit, output that does not decode or does not parse (`ValueError`, `SyntaxError`, `MemoryError`, `RecursionError`, `TypeError`), a result that is not a list or holds a non-string.
6. **The ahead check where no copy entry stands on the path (defect; Review A should-fix).** In the plugin's `pytest_sessionfinish`, an entry of the import path inside the Workspace is reported in `path_ahead` where it stands ahead of every entry inside the copy, and also where no entry inside the copy stands on the path at all (the old code's `ci is None` case). An entry behind the copy's entries still refuses nothing.
7. **Dead code out (Review A consider).** Remove `tree_path_at_commit`: `active_import_roots` already keeps only a root whose folder the tree holds (in the `--checkpoint` mode the archived copy at the commit), which is R9's rule; drop its `checkpoint`, `workspace` and `commit` parameters where nothing else needs them. In `import_root_is_absolute`, remove the branches that can never be true after the backslashes are turned into slashes (the `\\` forms and the `//` and `///` forms the leading `/` already covers); keep the leading `/`, the drive letter and `os.path.isabs`, and the line still holds the word `absolute` for every form R4 lists.
8. **The report (records; Review A should-fix).** Round 1's report claimed R7's live line held the format text and that M1 was caught by two tests; this round's report quotes the R7 line exactly as the source holds it, and each mutation result as pytest printed it. Write step 12's output after the report is otherwise complete.
