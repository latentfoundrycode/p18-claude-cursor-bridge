# BUG-003-r1 report

## Summary

`escape_field` now keeps a character only when it is printable and its code point is below 128, and every other character still becomes `\xNN`, `\uNNNN`, or `\UNNNNNNNN`, so a finding line is ASCII before it is written. In `collect`, a `types` or `traits` path that exists, is not a link, and is not a folder is recorded with `found.append((layer, "link"))` and is not walked, so it is printed as `FAIL (form) <root>/<layer>: <layer> - path is not a conditional-workflow file`, the same line a layer link already uses.

## How the change addresses the named cause

Defect 1: `escape_field` itself drops every non-ASCII character into the existing hex escape, so the bytes of a finding line no longer depend on the console encoding or on `errors="backslashreplace"`.

Defect 2: the `os.path.isdir` test in `collect` no longer `continue`s past a layer path that is a file; it records that path the same way a layer link is recorded, and the walk never opens it.
