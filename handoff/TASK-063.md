# TASK-063: The permission guard reads a command as the shell does (R-082)

## Objective
`bridge/cursor-bridge/permission-guard.py` is the Claude Code PreToolUse hook that refuses the actions the loop must never take (an override merge, a force-push, `git worktree remove`, a merge without the pre-merge record, a commit that skips its checks, a chain of state-changing commands inside a Workspace, the Cursor agent started around the shim). It parses the command rather than matching a pattern, but two holes and three false refusals remain. The holes: a command substitution inside double quotes (`echo "$(git worktree remove ../Worktrees/TASK-012)"`) is read as text, and a quote closes wherever the character before it is not a backslash, so a quoted string that ends in an escaped backslash (`echo "a\\" ; git worktree remove ../Worktrees/TASK-012`) hides everything after it. The false refusals: three tests read the raw command line instead of the parsed command, so `git commit -m "--no-verify"`, `git commit -m "set HUSKY=0 in CI"` and a `$(` in a quoted field of another `gh api` command after a `gh api graphql` call are refused. This increment makes both splitters read quoting, substitutions and escapes as bash does, moves the three raw-line tests onto the parsed command, and refuses an unquoted `&` inside a `gh api` argument with a remedy. Every refusal the guard has today stays. The supervisor's acceptance tests are written and committed; your work is to make them all pass without breaking the existing ones.

Satisfies: R-082 - The permission guard reads a command as the shell does (C5 as rescoped): a command substitution inside double quotes, `$(` or a backtick, is read as a command; a quote closes as bash closes it (no escape inside single quotes; inside double quotes a quote is escaped only by an odd run of backslashes), so a quoted string ending in a backslash hides nothing after it; the `gh api graphql` substitution test reads that command's own arguments, the `HUSKY=0` test the leading assignments, and `--no-verify` is read as an option of each of the seven git subcommands the guard holds to it (commit, push, merge, rebase, am, cherry-pick, revert) and not from another option's value; an unquoted `&` in a `gh api` argument is refused with a message that says what to quote; a process substitution (`<(`, `>(`) is read as a command substitution is, a substitution inside `${ }` is found, ANSI-C quoting (`$'`) closes by its own escapes, and a `$(` behind an odd run of backslashes outside single quotes is none; what a word expands to at run time (an indirect expansion, a variable in a command's place) stays outside the reading, stated in INVENTORY's threat-model row; every wrapper, `eval`, here-document, alias, GraphQL-mutation and launcher-bypass refusal stands, each held by a test, and the deny rules of `settings.bridge.json` are unchanged. (INVENTORY's threat-model row is the supervisor's records commit, not this increment.)

## Requirements
1. **Substitutions are commands, in both splitters.** `$(` to its matching `)` and a backtick pair are read as commands of their own inside double quotes as outside them, nested to any depth (`echo "$(echo "$(...)")"`), inside a here-string (`cat <<< "$(...)"`), and inside a parameter expansion `${ ... }` (inside double quotes or not). In `split_commands` each such command meets every refusal a top-level command meets. In `chain_parts` the chain operators inside a substitution count as they do at top level, so `echo "$(git add -A && git commit -m x)"` in a Workspace is refused for rule 8 as the unquoted form is today.
2. **Process substitution.** `<(` and `>(` to their matching `)` are read as a command substitution is.
3. **Quotes close as bash closes them.** Inside single quotes no character escapes: the next `'` closes. Inside double quotes a `"` is escaped only by an odd run of backslashes directly before it; an even run (an escaped backslash) leaves the quote to close. An ANSI-C string `$'...'` closes by its own escapes: `\'` and `\\` inside it are escapes, so an escaped quote closes nothing and a string ending in an escaped backslash closes at the next quote. Both splitters follow these rules.
4. **Escaped substitutions are text.** A `$(` or a backtick behind an odd run of backslashes, outside single quotes (at top level or inside double quotes), starts no substitution; behind an even run it does. A `$(` or a backtick inside single quotes is text.
5. **The graphql test reads the command's own arguments.** A `gh api graphql` command is refused with the existing message (it holds `graphql`) when one of its own arguments is built by a command substitution (`$(` or a backtick pair, quoted or not); a substitution in another command of the same line, such as a later `gh api ... -f body='see $(this)'`, no longer refuses it. The raw-line search at line 435 goes. The refusal still reaches a `gh api graphql` inside a wrapper, `eval` or a substitution, since those are read as commands.
6. **`HUSKY=0` and `--no-verify` are read from the parsed command.** `HUSKY=0` is refused only as a leading assignment of a git command whose subcommand is `commit`, `push` or `merge` (the set as built), also after other assignments (`X=1 HUSKY=0 git merge task-012`), with the existing message (it holds `HUSKY`); `HUSKY=0` inside a quoted argument is no assignment. `--no-verify` is refused only where it stands as an option of a subcommand in `HOOK_SKIPPERS`, all seven, never where it is the value of another option (`git commit -m "--no-verify"`, `--message=...`); the message keeps naming the subcommand and `--no-verify`. Commit's `-n` keeps its refusal as built (`git commit -n -m x` refused, `git push -n` passing), and the checkpoint and hand-off exemptions stay exactly as built.
7. **An unquoted `&` inside a `gh api` argument** (`gh api repos/o/r/pulls?state=all&per_page=1`) is refused with a message that tells the user to quote the argument; the word `quote` appears in it. Inside a Workspace, where the same line may also read as a chain, the refusal the user gets still names the quoting remedy. A single-quoted or double-quoted argument holding `&` passes, and a `&` that separates commands (`git fetch & gh pr merge 12 --squash`, the existing cases) keeps separating them and is refused or passed for what the commands are. What marks a `&` as inside an argument rather than between commands is your choice, stated in the report.
8. **What stays outside the reading.** A variable or an indirect expansion in a command's place (`$CMD worktree remove ...`, `${!name} worktree remove ...`) passes: the guard reads words, never a value. Do not add a refusal for them.
9. **Every refusal stays.** Every wrapper, `eval`, here-document, alias, GraphQL-mutation, `gh api` merge-endpoint, force-push, worktree-removal, premerge-record and launcher-bypass refusal of the existing tests stands, and a `gh api` read still counts as a state change for rule 8's chain. A here-document's body stays data unless a wrapper shell reads it. Behaviour this brief does not name stays as built; in particular the app's commit form `git commit -m "$(cat <<'EOF'\n<subject>\n\n<body>\nEOF\n)"`, which passes inside a Workspace today, still passes there: a substitution, a here-document's body and the newline that opens or closes it are not a chain by themselves.
10. **Linear time.** A command of 10,000 characters is read well within the hook's 15-second timeout: the scanning is a single pass (or a bounded number of passes) over the text, with no backtracking regular expression applied to the whole line and no re-scan per character. Recursion into nested substitutions does not re-read the whole line at each level.
11. **Your own cases**, each naming R-082 in its name, docstring or a comment, added to `tests/test_permission_guard.py` or `tests/test_permission_guard_a4.py` (whose `workspace` fixture is a scratch Workspace): (a) the app's commit form of Requirement 9 inside a Workspace passes, with a `checkpoint before TASK-003` subject and `--no-verify`; (b) the unquoted `&` of Requirement 7 inside a Workspace is refused and its message holds `quote`; (c) `git commit -m x --message="--no-verify"` passes and `git commit -m x --no-verify` is refused (the option after a message); (d) `env HUSKY=0 git push origin task-012` is refused. Every subprocess call in a case you add passes `creationflags=getattr(subprocess, "CREATE_NO_WINDOW", 0)` and a timeout. You may add more.
