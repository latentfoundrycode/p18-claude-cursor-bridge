## Why a resolution round

TASK-063 (R-082: the permission guard reads a command as the shell does) has had two builder rounds. Both were rejected by Review A (the diff reviewer) and the security audit, and **both regressed refusals the guard made at the checkpoint fae0860**: round 1 lost six (a glued `&`, an unquoted `$(` building a graphql query, `-m` before `--no-verify` for rebase and am, `HUSKY=0` before eval or a wrapper), round 2 lost at least nine others (below). The loop's rule: after a second fix that regresses, a resolution round, never a further guessed brief; a class line never lifts a round for a regression the previous fix caused. This is that round.

The next builder round is round 3, the code gate's ceiling: only the five blocking classes send work back after it, and every finding below is security (a refused command that runs), so a design that keeps producing such findings cannot converge under the ceiling.

## What round 2's readers found (each reproduced as the hook runs; WR = `git worktree remove ../Worktrees/TASK-012`, NL = a new line)

By mechanism, the two readers' findings combined:

1. **Backtick pairs.** The inline backtick loop pushes quote and substitution frames and pops only split frames: `` echo `echo "x"` ; WR ``, `` echo `echo 'x'` ; WR ``, `` echo `echo $(date +%Y)` ; WR ``, `` echo `echo \`WR\`` `` exit 0 (fae0860: 2).
2. **Here-documents.** The text after the delimiter on the operator's line is dropped: `cat <<'EOF' ; WR` NL `x` NL `EOF`, `cat <<'EOF' > m.txt && git push --force origin main` NL `x` NL `EOF` exit 0 (fae0860: 2). A here-document inside `"$(` is not recognised, so the app's own commit form with an apostrophe in its body hides the next line: `git commit -m "$(cat <<'EOF'` NL `fix: don't crash` NL `EOF` NL `)"` NL `git push --force origin main` exit 0 (fae0860: 2). `<<` with no delimiter crashes (exit 1). `<<` in arithmetic (`echo $((1<<2)) ; WR`) is taken for a here-document (exit 0). Delimiter quote removal, `<<-`, a shell reading through a pipe or inside a substitution, and a recursion through `absorb_expanded_heredoc` (exit 1 at 600 to 1000 nested here-documents).
3. **Word reading.** `_tokenize_parsed`, used whenever `$'` or `$"` appears anywhere, splits words wrongly: `X=$'1' WR`, `git push --fo"rce" origin $'main'`, `git $'work'tree remove ...` exit 0 (fae0860: 2 for the first two). `$'...'` decoding ignores bash's cut at a NUL (`git push $'--force\x00x' origin main` exit 0).
4. **`HUSKY=0`.** Only eval, bash, sh, setsid and winpty with a git first word: `HUSKY=0 bash -c "true; git commit -m x"`, `HUSKY=0 cmd /c git commit -m x`, `HUSKY=0 python -c "import os; os.system('git commit -m x')"`, `HUSKY=0 find . -exec git commit -m x ;` exit 0 (fae0860: 2).
5. **`${...}` and case.** `echo ${x:-{} ; WR` exit 0; `echo ${x:-${y:-$(true)}} ; WR` exit 1 (KeyError); `` echo ${x:-`WR`} `` exit 0; `git log -1 "$(echo upper case in titles)" ; WR` exit 0 (case tracking fires on ordinary words) (fae0860: 2 for each).
6. **The checkpoint exemption spoofed.** `echo $(echo checkpoint before TASK-001) ; git commit --no-verify -F msg.txt` exit 0 (fae0860: 2): the subject is taken from any substitution's first line.
7. **Time.** Four shapes of 9,000 to 60,000 characters run 20 to over 40 seconds (the stack scanned at every character, the buffer joined and searched at every space or new line inside a substitution); the depth bound is defeated by a double quote inside `${`.
8. **PowerShell.** The second reading is not applied to rule 8 or to a wrapper under the Bash tool; a backslash-newline is joined under PowerShell; and PowerShell syntax neither reading models (`` "`"" ``, `@'` here-strings, `<# #>` comments, a lone carriage return) hides a command (these four pass at fae0860 too).
9. **Structure.** Four scanners with their own quote state remain (the inline backtick loop, `_tokenize_parsed`, `parse_heredoc_delim`, the `gh api` check), a recursion through `absorb_expanded_heredoc`, and substitution bodies read twice: the cause round 2's brief named, reproduced.

## The question

How should TASK-063 go on, so that it converges within the ceiling without losing a refusal of fae0860?

## The candidates

**A. Round 3: a corrected brief, the same design.** Name every finding above with its reproduction and the corrections both readers proposed (find a backtick's end first and push its body as a fresh context; read the operator line after a here-document's delimiter; a here-document inside `$(`; words produced by the one reader; HUSKY through recursion; linear time; the PowerShell readings), and let the builder rewrite `read_shell`. For: it is the approved design as written ("the other forms in which bash runs or hides a command are read by the same rules"). Against: two rounds each found a dozen new holes and regressions; a hand-written reader of bash's full grammar has an open-ended edge set, and after round 3 every new hole is security and blocks again, so the gate would run past the ceiling on the same subsystem.

**B. Change the design: read a defined subset exactly, refuse the rest.** The guard reads with certainty only a stated subset of the shell's grammar, and refuses, with a remedy that names the form ("the guard cannot read X with certainty; write it more simply"), every command that uses a construct outside the subset or whose reading is not certain. The subset is what the loop and a model's ordinary commands use: words with single quotes, double quotes and backslash escapes; `$(...)` and backtick pairs read as commands (a backtick pair's end found first); the separators (`&&`, `||`, `;`, `|`, a new line, every single `&`); a `#` comment at a word's start; a here-document whose delimiter is a plain word or a quoted plain word, recognised at top level and inside `$(`, with the rest of its operator line read; the leading assignments and the existing wrappers. Outside it, refused as unreadable: `${...}` that holds a quote, a substitution, a backtick or a brace; process substitution (or read as `$(`, the round decides); `case`, arithmetic `((`/`$((`, ANSI-C and locale strings other than a whole word (decoded), unclosed contexts, a nesting past a small bound; under the PowerShell tool, a backslash before a quote, a backtick before a quote, `@'`/`@"` here-strings, `<#`, a lone carriage return. A false refusal costs one rewrite of the command; a hole costs a refused action. For: the edge set becomes closed and testable: a hole can only be inside a small subset, and everything else fails closed; it also covers forms both readings found outside any brief (PowerShell syntax). Against: it changes the approved design paragraph (read by the same rules becomes read or refused), a material change after the design gate, told to the owner by rule 58; some harmless forms a model writes are refused (`diff <(git log) <(git status)`, `echo ${x:-default}` stays readable, `$((1+1))` would not); the 116 instructed commands and the app's commit form must stay inside the subset, which must be checked.

**C. Narrow the increment.** Revert to fae0860 and build only the design's two reproductions (a command substitution inside double quotes read as a command; a quote closing by the parity of its backslash run), the three moved tests (graphql, HUSKY, `--no-verify` on the parsed command) and the `gh api` `&` remedy, on fae0860's splitters; the rest of R-082's forms become leads of a later release. For: smallest change, fae0860's refusals kept by construction. Against: it drops part of a requirement the owner approved (scope, the owner's to decide), and it leaves the holes both readers found that fae0860 already has (comments, here-documents, ANSI-C words) open.

## The supervisor's leaning, for you to test
