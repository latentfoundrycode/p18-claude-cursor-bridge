**Ruling 1. A later success clears a finding found in this window** (Review A round 2 B1). A run with exit 1 is the standing finding only if no completed run of the window created later than it (by parsed `created_at`) ended `success`. Where such a success exists, the finding found in this window is cleared:
- no `finding standing:` line;
- the ledger's `finding_standing` is null;
- where the week's last completed run is a success, the section is green.

This is the same clearing rule as round 2's Ruling 3 for a finding standing from before. Fault: `scan_project`, the exit-1 loop at lines 948-960 and the assignment at 964-965 (`if exit1_id is not None: new_standing = exit1_id`). It sets the standing finding from any exit-1 run without checking for a later success of the window. A green week therefore shows a standing finding, and the ledger keeps it.

**Ruling 2. The newest exit-1 run is the standing finding** (Review A round 2 B2). Where several runs of the window read exit 1, the standing finding is the newest of them by parsed `created_at`, never by the order the reply lists them (GitHub lists newest first). Fault: `scan_project` lines 948-960. The loop walks `failures` in the reply's order, and each exit-1 run overwrites `exit1_id`, so the oldest one (the last in the reply) wins.

**Ruling 3. A failed alerts read never replaces the scan's remedy** (Review A round 2 B3). A failed alerts check or open alerts list keeps the week's kind with its own remedy:
- the rerun command for a scanner failure or no completed run;
- enable-then-rerun for a disabled workflow;

Beside it, the section adds the alerts failure's `read failed:` line and its remedy: the login's scope (`gh auth refresh -s <scope>`) and the repository's Security tab. Round 2's handling of a green week with a failed alerts read (lines 999-1001: the kind becomes `finding`, the `scan:` line says the last run ended success, the word green does not appear) stays.

**Ruling 4. A standing finding never replaces the week's kind** (Review A round 2 B4). Where a finding stands from before, the section keeps the week's own kind and remedy:
- no run in the window: `no completed run` with the rerun command;
- only runs in progress: `no completed run` with no rerun;
