# BUG-002 (round 2): remove the list `check_head` fills and never reads

## Objective
Round 1 of BUG-002 fixed the `Workflows:` head's separators and was approved by every reviewer. Two reviewers then named the same leftover independently, which makes it blocking: in `bridge/cursor-bridge/workflow-check.py`, `check_head` still builds the list `traits_in_head`, and since round 1 nothing reads it. Remove the list; change nothing else. This is a behaviour-preserving cleanup: every finding `check_head` emits stays exactly as it is.

**The code as it stands** (`check_head`, from line 602):

```python
    types_found = []
    subs_found = []
    traits_in_head = []
    for names in names_by_seg:
        for name in names:
            if name == "":
                findings.append(("form", path, "-", "empty name in the Workflows head"))
                continue
            if name in tables["workflow_by_name"]:
                types_found.append(tables["workflow_by_name"][name])
            elif name in tables["sub_by_name"]:
                subs_found.append(tables["sub_by_name"][name])
            elif name in tables["trait_by_name"]:
                traits_in_head.append(name)
            else:
                findings.append(("unknown", path, name, "name is not in the open list"))
```

The trait branch must stay in effect: a trait name in the head is not `unknown` (it is the shape `form`, which the exact comparison later in the function already gives). Only the list goes.

Satisfies:
- R-014 — `workflow-check.py` verifies: every change targets an existing extension point; replace/set appears only in a type or sub-workflow and replace only on a replaceable phase; trait additions only add; every sub-workflow names an existing type workflow; every project's `Workflows:` line names, per part, exactly one product type, at most one sub-type of that type, and traits, all in the open list — an unwritten type or sub-type fails (pauses the project), an unwritten trait is flagged, non-fatal (§6.7).
- R-015 — The status file records a `Workflows:` line per part (product type, sub-type, traits) beside the `Phase:` line.
