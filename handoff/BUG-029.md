# BUG-029: the launcher knows cursor-agent by one exact name, and a holder's record is published before its `slot taken` line

## Objective

Fix the following confirmed defect — repair the named cause, nothing else. There are two causes. Both live in `bridge/cursor-bridge/bridge-run.py`, and both are fixed in this one brief because they edit the same file.

**Cause 1, in one sentence.** `head_of` strips `.exe` and `.cmd` wherever they stand in a name, so `kind_of` and `accepted` treat a file named `cursor-agent.exe.cmd` as the agent, while `resolve` swaps in the real agent only for an exact basename in `AGENT_NAMES`; such a file is therefore allowed and runs as itself through `cmd.exe`, without the stripped environment (`is_agent` False), and, when labelled `--kind review`, without the slot. A cursor-agent given by a path (`C:/x/cursor-agent`, `./cursor-agent`) is accepted by its basename, and `resolve` silently swaps the real agent in for it.

**Cause 2, in one sentence.** `acquire_heavy_slot` writes `bridge-run: slot taken <time>Z` first, and only then reads this process's creation time and publishes the holder record, so a waiter that polls in between reads the previous holder's record, or none, and says `held by unknown`; at scale 1 its next waiting line comes a minute later.

**Evidence (from the code and docs on this branch, `fix/BUG-029`, cut from `origin/main` after TASK-029 merged as PR #89).**
- `bridge-run.py:145-146`: `return os.path.basename(argv[0]).lower().replace(".exe", "").replace(".cmd", "") if argv else ""`.
- `bridge-run.py:1130`, in `resolve`: `if os.path.basename(argv[0]).lower() in AGENT_NAMES:`, where `AGENT_NAMES = ("cursor-agent", "cursor-agent.cmd", "cursor-agent.exe")` (:104).
