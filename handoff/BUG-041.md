# BUG-041: the review guard, a snapshot deleted after it was taken reads as one never taken

## Objective
Fix the following confirmed defect — repair the named cause, nothing else.

- **Root cause:** `load_snapshot` returns `None` for any snapshot file that is not there, and both its callers return 2 before `snapshot_rewritten` runs, so the copy of the hash that `snapshot` wrote outside the checkout (FB-037), the record that a snapshot was taken, goes unread.
- **Evidence (`docs/debug/BUG-041.md`):** after the launch, a hook planted, a branch made and `.git/bridge/review-<nnn>.json` deleted: `verify` exits 2 with "no snapshot ... run snapshot before the launch": no GATE-INTEGRITY, no void, nothing restored. `snapshot` on the same tree exits 0 and takes the hook and the ref as its baseline, the next launch verifies and premerges clean, and the next `git commit` runs the hook. Without the delete, `verify` exits 1.
- **Reproduction tests, in `tests/test_bug041.py`, that fail on the code today and must pass:** `test_bug041_a_deleted_snapshot_is_a_flag_and_voids_the_launch`, `test_bug041_premerge_refuses_a_deleted_snapshot_as_a_flag`, and the negative cases `test_bug041_negative_a_deleted_snapshot_restores_nothing_and_runs_no_git`, `test_bug041_negative_the_voided_launch_stays_voided_under_the_next_snapshot`, `test_bug041_negative_a_launch_before_the_round_is_not_voided`.
- **Invariants in the same file, which pass today and must stay green:** `test_bug041_negative_a_snapshot_never_taken_stays_a_cannot_verify`, `test_bug041_negative_the_snapshot_and_its_copy_both_gone_stays_a_cannot_verify`, `test_bug041_negative_a_standing_snapshot_is_unchanged`.

Satisfies: R-042 — a GATE-INTEGRITY flag spends nothing and no flagged launch is admitted.

## Requirements
**The existing behaviour you may change is what these requirements name, and nothing else.**

1. **The deletion is a flag.** In `load_snapshot`: where the snapshot file is not there and its hash copy (`hash_copy_path(common, nnn)`) is a file, it returns an empty dict in place of the snapshot, with `root`, `common` and a hash of `None`, and prints nothing. `verify` then reaches its existing rewritten return: GATE-INTEGRITY, exit 1, the checkout not restored, no git command, `record_flagged_launch(common, root, nnn, None)`. In `snapshot_rewritten`, which names the deletion: where the snapshot file is not there, it prints one line starting two spaces then `GATE-INTEGRITY`, holding the word `deleted` and naming both paths, and returns `"rewritten"`. Its existing line for a differing hash stays word for word, and its read of the copy and that read's `"missing"` return stay first. "Not there" and "is a file" are `os.path.isfile`, the test `load_snapshot` already makes, in both functions.
2. **`premerge` follows, unchanged in code.** It reaches its existing rewritten return by the same route: GATE-INTEGRITY, exit 1, nothing written. `cmd_verify` and `cmd_premerge` need no edit of their own; if one seems to, stop and report it.
3. **Everything else stays.** No snapshot and no hash copy is CANNOT VERIFY, exit 2, by the existing line. Both gone reads the same (a stated limit, recorded on the supervisor's side). A standing snapshot is unchanged, and `load_snapshot`'s catch stays `ValueError` and `RecursionError` only.
4. **Generators.** Run after the code is final, from the Workspace root: `python tools/dump-cli.py`, then `python tools/make-manifest.py`. If `make-manifest.py` changes `bridge/cursor-bridge/VERSION`, stop and report it.
