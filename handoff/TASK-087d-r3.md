# TASK-087d: `--review-alt` acts on the profile the resolve picks

Round cause: Review A, round 2, blocking 1 (behaviour): an alternate that did not answer its probe for an earlier profile is probed again by the request for the profile in use (bridge/cursor-bridge/roster-check.py).

## Objective
`roster-check.py --review-alt <reason>` resolves a profile's alternate reviewer (`review_b_alt`) on request, for a provider's safety refusal of Review B. Round 1 made the request act on exactly the profile the resolve without the request picks, through one reading of a profile, `_evaluate_profile(prof, verbose)`, which the request path and the plain resolve loop both call. Round 2 made the request reuse the alternate's answer where the evaluation of the profile in use had probed it: `_evaluate_profile` returns `alt_probe_ok` (set at line 1320, where it probes the alternate in the role `review_b_alt`), and the request reads `in_use_ev.get("alt_probe_ok")` (lines 1398 to 1412), probing only where it is None. Rounds 1 and 2 stand in this checkout as committed; Review A approved everything of round 2 but one defect, and all of that is kept. Round 3 repairs that defect, which Review A reproduced: two profiles name the same `review_b_alt`; the first profile's Review B is excluded (a mark or the exhausted pool), so its evaluation probes the alternate, which does not answer, and that profile is skipped; the profile in use then resolves with no deviation, so its `alt_probe_ok` is None; the request probes the same model in the same role again, and a second answer grants the alternate the run had just read as not answering. After this round one run reads at most one answer from a model in the role `review_b_alt`, across every `_evaluate_profile` call and the request, and every reader acts on that one answer.
