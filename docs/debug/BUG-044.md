# BUG-044 — the migration writes a plan header its readers refuse (R-062)

Found by stage H2's review of release B2's text, round 1 (STAGE-H2-r1, 2026-11-11; tag `stage-review/H2-1`), both reviewers rejecting, each with a reproduction in a temporary folder.

## Symptoms (reproduced)
1. **A heading outside any stage** (Review A, the bridge part). A plan whose `### TASK-001` stands before its first `## ` heading: `plan-check.py --no-git` gives `RESULT: OK` before the migration; `records-migrate.py` prints `wrote docs/BUILD_PLAN.md`, exit 0, the header holding TASK-002 only; afterwards `plan-check.py --no-git` gives `SHAPE: TASK-001 has a ### heading but stands outside any stage`, `DEPENDS: TASK-002 depends on TASK-001, which does not exist`, `RESULT: 3 problem(s)`, exit 1, and `plan_header_refusal` refuses wherever a merge unit is checked.
2. **A bold Satisfies line** (Review B). A plan with `**Satisfies:** R-099` beside a plain `Satisfies: R-004`, and `**Satisfies**: R-011` alone: `completion-check.py --mode plan` gives `RESULT: OK` before the migration; the migration writes `satisfies: [R-004]` and `[]`; afterwards `HEADER DISAGREES: satisfies`, exit 1. The same plan on plain lines stays OK.

Reproduction tests: `tests/test_bug044.py`, red on main 86a37e3 (the run's line in the fix's records).

## Hypotheses
- **H1 — the read-back proves agreement with the composer's own reading, never acceptance by the readers.** `_validate_read_back` (records-migrate.py:469-484) runs `read_header`, `check_header` and `header_agrees(kind, header, fallback_for(...))`; the fallback is the reading the header was composed from, so agreement is guaranteed by construction, while the headed plan's readers apply two further rules the header-less plan never met: the shape rule (`walk_plan_prose_body`'s `outside_stage`, read by `plan_header_refusal` bridge_env.py:3463-3467, `plan_header_findings` 3510-3518, `plan_check_parse` 590-594) and completion-check.py's outside-header scan (223-233, `plan_r_ids_outside_headers` bridge_env.py:3273-3294, whose bold branch the fallback's `FIELD_RX` lacks). Discriminating observation: in both reproductions the written header passes `header_agrees` and fails a reader's rule that only a headed plan meets.
- **H2 — the fallback's reading is wrong.** Discriminating observation: the header-less readers (stage H1's design: one reading) use the same fallback and give OK on both plans before the migration, so the fallback is right for a header-less plan; changing it would change every header-less plan's reading, which release B2 does not touch.

## Confirmed cause
H1, on the reviewers' traces (code lines above) and the reproductions: the composed header is checked against itself. H2 rejected.

## The fix (the brief BUG-044)
The migration refuses, before writing, a plan its headed readers would refuse, listing it `cannot read <path>: <reason>` with the repair (a heading moved under a `## ` stage; a bold Satisfies line written as a plain `Satisfies:` line), and the read-back of a plan also runs those readers' rules as a second net. Riding: the root's path escaped in the plan glob; `merge_unit: null` for a brief with no `Merge unit:` line; calibrate-bridge.md's item names the new repairs and the exit 2 and exit 3 stops; run-parameters.md's lift sentence says which lines are omitted.
