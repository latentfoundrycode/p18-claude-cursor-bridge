# BUG-043 — the loop's claim that builder-written code never runs with the owner's environment

Found by stage T2's review, round 2 (Review A's bridge part, its B1, a REJECT, graded security; Review B silent), confirmed by reading `bridge/cursor-bridge/workflow/phases/delegation-loop.md` at origin/main 603b2d4. It is a defect of text, its own cause; the tests of `tests/test_bug043.py` written first fail on that commit for the reason given (`run/agent/BUG-043-r3-checkpoint.out`).

**Symptom.** Step 4 said "code the builder wrote never runs in the loop with the owner's login or secret-like variables (D-004, R-052)", `docs/DESIGN.md` said the same and D-004's note said a run without the flag is instructed only for a driver under a recorded Decision. Six lines on, step 4 let a run of the increment's own test files run in the foreground, the supervisor's or `test-runner`'s, and `bridge/agents/test-runner.md` repeated it. That run is direct, with no launcher and no `--strip`: an execution of the builder's tests, on every increment, on an ordinary layout, before any reviewer has read them, with the owner's `USERPROFILE`, `gh` login and secret-like variables. `tests/test_release_t_strip.py` skips in exactly that case, so no test saw it, and D-004 drew no such edge, so an auditor reading every crossing was told the crossing did not exist.

**Confirmed cause.** R-052's words are "the loop's suite launches", and a suite is defined as more than the increment's own test files. TASK-041 wrote the general claim over that narrower change. The exposure predates the stage; the claim is the stage's.

**The class.** Security, not a regression: untrusted input, files a builder writes, reaches it on every increment (INVENTORY's by-class row: a security finding is judged by whether untrusted input can reach it). REVIEWERS DISAGREE, Review B silent; correctness, not intent; decided for the fix, a false claim of a security property being the one thing the release says it closes.

**The fix.** Close what can be closed and state the rest as a class:
- the increment's own test files go through the launcher, `--strip`, as the supervisor's launch in the background, and `test-runner` reads the file: a foreground launch with the slot held is moved to the background by the app, stays queued with no pid and no log row, and no program can stop it (Review A's B2 of the first text);
- a stripped suite or own-file run that fails for want of a variable takes `--key-file`, and is never run again without `--strip`; a 125 on a runner you know is a defect to fix (the audit's A5, its A1 of the second text); a home variable in a key file would undo the strip, since the launcher applies keys after it (Review A's S2 of the second text; a program item);
- the claim now says what the flag does, not what every launch of the loop does: it withholds the owner's `gh` and git login and the environment's secret-like variables, and a key file hands the code what it names, so it holds only what the brief or the inventory names (the second text's "no launch but a driver" was false against `# wake`'s direct run and the key file in its own next clause: Review A's B1, the audit's B3);
- whatever else runs what a builder wrote on this computer runs in a session's own environment, stated limits, among them: a runner the launcher refuses, a benchmark or profile, a build, a type check or a linter, a hook a commit runs, a reviewer's or auditor's own run, a root-cause reproduction, an installer rehearsal, a live smoke and a stage demonstration's start of the product. The first text's count of three was a new absolute with the old claim's fault, disproved by its next sentence (Review A's B1 and the audit's B1, convergent, security). The owner is told (rule 58);
- after a run of what a builder wrote, step 4 reads `.git/config` and lists `.git/hooks` as files, a class of lines a flag, and says it is a check, not a boundary. A stripped test can write `core.fsmonitor`, and the session's next git command runs it with the owner's login, reproduced end to end (the audit's B1 and B2 of the second text, Review A's B2 and S1; the first text read only after a builder run, for two keys). Text cannot hold the order, since a git command of the session or the app may run first (assumed, not verified). The threat model is recorded for R-050: the strip withholds what a run is handed, never what it can reach on purpose (KP-032). The launcher's comparison before and after a run is a program item, and the owner is told it is not closed by this release.
