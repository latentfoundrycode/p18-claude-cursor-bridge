## 1. A checkpoint run is refused when a copied conftest.py imports what the increment adds
- **Symptom:** `mutation-run.py --checkpoint` exits 2 with `mutation-run: resolution check failed (pytest exit 4)` when a conftest.py on the way to a new test imports a module or a name the increment adds; before BUG-030 the same run went on (tests-mutation-pace, Blocking).
- **Hypotheses:** (a) the copied conftest.py is not copied where pytest reads it; (b) it is copied, and pytest cannot load it on the checkpoint's code. Discriminating observation: pytest's exit code and line. The run prints `resolution check failed (pytest exit 4)`: pytest's usage-error exit, which it gives when a conftest.py fails to import at startup ("ImportError while loading conftest"), so the file was read and failed to load: (b).
- **Confirmed cause:** BUG-030's archive_checkpoint copies the working tree's conftest.py files over the checkpoint's (mutation-run.py, the conftest copy); run_resolution_check refuses any pytest exit other than 0 or 2 (`rc not in (0, 2)`), and checkpoint_collect_refused excuses only exit 2, so a conftest.py that cannot load on the old code refuses the whole run, where the tests it guards cannot be run against the checkpoint and are, by step 4's rule for a collection error, `not run`.
- **Reproduction:** tests/test_bug032.py::test_bug032_a_conftest_importing_what_the_increment_adds_lists_its_tests_not_run (the CALC fixture; the working tree adds demo/newmod.py and a tests/conftest.py that imports it; the new test uses its fixture: exit 2 today, must list the test `not run` and not be refused).

## 2. scope-check.py opens a builder window for a launch that never got the slot
- **Symptom:** a `supervisor:` test commit made while a builder launch waited for the slot and gave up (exit 123) is counted as drift, though no builder ran (tests-guard C2, tests-launcher C5, launcher C1; convergent).
- **Confirmed cause:** builder_windows (scope-check.py) takes every `kind: builder` row, a `"slot": "not free"` row included, and since BUG-030 its window runs `waited` + `seconds` + 120 seconds from its `id`; BUG-030 made roster-check's built_by and the launcher's class line skip such a row, which started no command.
- **Reproduction:** tests/test_bug032.py::test_bug032_a_launch_that_never_got_the_slot_opens_no_builder_window (a started row opens one window, the precondition; a `slot: not free` row opens one today, must open none).

## 3. pace-report.py reads a launch that never got the slot as a launch
- **Symptom:** a round whose class-line launch ended at 123 and was relaunched without the line reads `class` in the pace report's lift column, and the increment's start is the refused launch's time (tests-launcher C5, launcher C3, briefs-ceiling C2; convergent).
- **Confirmed cause:** _lift_map and _start_times (pace-report.py) read every row of the ID from runs.jsonl, a `"slot": "not free"` row included.
- **Reproduction:** tests/test_bug032.py::test_bug032_the_pace_report_reads_a_launch_refused_the_slot_as_no_launch (a refused row with `lift` class before a started row without: `{1: 'class'}` today, must be `{1: 'none'}`; the start must be the started row's).

## 4. The branch rule refuses the refactoring pass's second candidate and its snapshot
- **Symptom:** on `refactor/<stage>`, after REFAC-003's brief ran, REFAC-004's is refused `branch rule: REFAC-004 is not on this branch (counted: REFAC-003)`; refactoring-pass.md step 4 delegates one REFAC brief per candidate on that one branch, and step 6 takes one gate pass for the whole branch (modules, Blocking; verified by the supervisor in the code and by the test).
- **Confirmed cause:** bridge_env.branch_allows_id, which bridge-run.py and review-guard.py both call, allows only the IDs the branch's first brief declared (branch_declared_ids) until they merge; a `Merge unit:` line admits only the plan's increment IDs (bridge-run.py), and a REFAC ID is never one; the guard refuses the pass's snapshot under the stage's name for the same reason.
- **Reproduction:** tests/test_bug032.py::test_bug032_a_refactoring_branch_takes_every_candidates_brief (REFAC-004 refused today on `refactor/B5`, must run; TASK-005 there refused, and REFAC-004 after REFAC-003 on `task-003` refused, the preconditions) and ::test_bug032_the_refactoring_pass_snapshot_is_taken_on_its_branch (a snapshot `REFAC-B5` on that branch must be taken; one of TASK-005 refused, the precondition).
